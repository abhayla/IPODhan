## Story

**As a** BSE scraper validation system,
**I want** to make `symbol` and `leadManagers` fields optional for RIGHTS and NCD categories,
**so that** valid Rights/Debt IPOs with missing optional fields can pass validation and be persisted to the database.

---

## Context

**Note**: This story complements Story 11.5 Task 5, which already includes the conditional validation pattern. This story can be implemented as part of Story 11.5 or independently if needed.

**Current Problem**: Validation schema requires `symbol` and `leadManagers` as mandatory for all IPO categories, causing Rights/Debt IPOs to fail validation even when other data is complete.

**Impact**: 11 BSE IPOs (8 Rights + 3 Debt) fail validation unnecessarily due to missing optional fields that Rights/Debt IPOs may legitimately not have on BSE detail pages.

## Implementation

### Solution Pattern (from Story 11.5)

```typescript
// File: scraper/src/utils/validators.ts

export const bseDetailSchema = z.object({
  symbol: z.string().nullable(),  // Changed from z.string()
  leadManagers: z.array(z.string()).nullable(),  // Changed from z.array(z.string())
  category: z.enum(['MAINBOARD', 'SME', 'RIGHTS', 'NCD']),
  openDate: z.string().nullable(),
  closeDate: z.string().nullable(),
  priceRangeMin: z.number(),
  priceRangeMax: z.number(),
  issueSize: z.number(),
  lotSize: z.number(),
  faceValue: z.number(),
  registrar: z.string().nullable(),
  sponsorBanks: z.array(z.string()).nullable(),
  issueShares: z.number(),
}).refine((data) => {
  // For MAINBOARD and SME, symbol and leadManagers are required
  if (data.category === 'MAINBOARD' || data.category === 'SME') {
    if (data.symbol === null || data.leadManagers === null) {
      return false; // Validation fails
    }
  }
  // For RIGHTS and NCD, symbol and leadManagers are optional
  return true;
}, {
  message: 'Symbol and leadManagers are required for MAINBOARD/SME IPOs',
  path: ['symbol', 'leadManagers'],
});
```
