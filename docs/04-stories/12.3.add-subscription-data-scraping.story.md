# Story 12.3: Add NSE Subscription Data Scraping for Cool Caps IPO

## Status
**Ready** - High Priority (P1)

## Story
**As a** IPO investor,
**I want** real-time IPO subscription data (QIB, NII, Retail, Total) from NSE,
**so that** I can gauge demand and make informed investment decisions during the IPO period.

## Problem Statement
Cool Caps Industries Limited shows **Subscription: N/A** on IPODhan, but NSE "Bid Details" tab shows complete subscription breakdown:
- QIB: 9,000 shares
- NII: 66,27,000 shares
- Retail: 1,63,29,000 shares
- Total: 2,29,65,000 shares
- Last Updated: 15-Mar-2022 17:00:07 hrs

This is a **CORE FEATURE** of the platform that is not working.

## Acceptance Criteria
1. Scraper must fetch subscription data from NSE "Bid Details" tab
2. Database must store subscription snapshots in `subscriptions` table (time-series)
3. Cool Caps must show subscription breakdown (not N/A)
4. Subscription data must include timestamp from NSE ("Updated as on...")
5. UI must display subscription in times format (e.g., "75.04x subscribed")
6. UI must show category-wise breakdown: QIB, NII, Retail with individual subscription multiples
7. API endpoint `/api/ipos/[slug]/subscription` must return subscription data
8. Cache subscription data with 5-minute TTL (CacheTTL.SUBSCRIPTION_LATEST = 300)
9. Handle NULL values gracefully (show "N/A" if subscription not yet available)
10. For past IPOs (like Cool Caps 2022), store final subscription data as historical record

### NSE Subscription Data Structure (from validation)
**NSE "Bid Details" Tab** shows table with columns:
- SR. NO.
- CATEGORY (QIB, NII, Retail, Total)
- NO OF APPLICATIONS RECEIVED (often "-" for SME IPOs)
- NO. OF SHARES BID FOR (e.g., "9,000", "66,27,000")

**Sub-categories**:
- QIB: FIIs, Domestic FIs, Mutual Funds, Others
- NII: Corporates, Individuals (>2 lots), Others
- Retail: Cut Off bids, Price bids

**Update Timestamp**: "Updated as on 15-Mar-2022 17:00:07 hrs"

### Subscription Calculation Formula
```typescript
// Given issue size and category quotas
const issueSize = 3060000; // Cool Caps: 30.6 lakh shares
const qibQuota = issueSize * 0.50;    // 50% for QIB
const niiQuota = issueSize * 0.15;    // 15% for NII
const retailQuota = issueSize * 0.35; // 35% for Retail

// Calculate multiples
const qibTimes = qibSharesBid / qibQuota;
const niiTimes = niiSharesBid / niiQuota;
const retailTimes = retailSharesBid / retailQuota;
const totalTimes = totalSharesBid / issueSize;

// Cool Caps example:
// QIB: 9,000 / 1,530,000 = 0.0059x (0.59%)
// NII: 6,627,000 / 459,000 = 14.44x
// Retail: 16,329,000 / 1,071,000 = 15.24x
// Total: 22,965,000 / 3,060,000 = 7.50x
```

### Cache Strategy (from CACHING_STRATEGY.md)
- **TTL**: 300 seconds (5 minutes) for active IPOs (CacheTTL.SUBSCRIPTION_LATEST)
- **Cache Key**: `subscription:latest:{ipoId}`
- **Invalidation**: After every scraper run (new snapshot inserted)
- **Pattern**: Cache-aside via `BaseRepository.getFromCache()`
