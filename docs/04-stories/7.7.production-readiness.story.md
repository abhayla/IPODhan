## Story
**As a** platform administrator and end user,
**I want** all critical production blockers fixed including missing pages, broken routing, and incomplete data integration,
**so that** the IPODhan platform is fully functional, displays live data, and is ready for production deployment with a professional user experience.

## Problem Statement

Comprehensive QA testing (January 10, 2025) revealed critical issues preventing production deployment despite excellent UI/UX foundation and working core features. The platform scored 7.5/10 for production readiness with the following blockers:

### Critical Production Blockers:
1. **Lot Calculator 404 Error** - Core feature completely unavailable at `/tools/lot-calculator`
2. **Missing Core Pages** - Affiliates, Resources, About pages return 404 despite navigation links
3. **No Live Subscription Data** - Dashboard and detail pages show "N/A" instead of real subscription percentages
4. **Missing GMP Data** - Grey Market Premium data not displayed despite Chittorgarh scraper availability
5. **Rating System Not Implemented** - All IPOs show "Not Rated" despite rating methodology documentation
6. **Missing Registrar Information** - Registrar details show "N/A" on IPO detail pages
7. **Non-functional Filters** - Dashboard filter dropdowns present but not filtering results
8. **No Loading States** - Brief "Loading..." text instead of professional skeleton screens

### Impact:
- **User Experience:** Broken links and missing data create unprofessional impression
- **Core Functionality:** Lot calculator is primary tool for IPO investors - unavailable
- **Data Integrity:** Live scraped data exists but not displayed to users
- **Competitive Disadvantage:** Competitors show GMP, ratings, and subscription data
- **Production Deployment:** Cannot launch with these critical gaps

## Acceptance Criteria

### 1. Critical Routing Fixes
1. Lot Calculator page loads successfully at `/tools/lot-calculator`
2. Affiliates page loads successfully at `/affiliates` with broker list
3. Resources page loads successfully at `/resources` with IPO guides and tools
4. About page loads successfully at `/about` with company information
5. All navigation links work without 404 errors

### 2. Live Data Integration - Subscriptions
1. Dashboard IPO cards display real subscription data from NSE/BSE scrapers
2. IPO detail pages show QIB, NII, Retail subscription percentages
3. Subscription data updates every 15-30 minutes via scheduler
4. "Last Updated" timestamp displayed for subscription data
5. Fallback to "Not yet subscribed" for IPOs without data (not "N/A")

### 3. GMP Data Integration
1. IPO detail pages display GMP (Grey Market Premium) from Chittorgarh scraper
2. GMP shown as absolute value (INR) and percentage
3. GMP trend indicator (up/down/stable) based on historical data
4. "Last Updated" timestamp for GMP data
5. Disclaimer about GMP volatility and unofficial nature

### 4. Rating System Implementation
1. Rating algorithm implemented based on `docs/rating-methodology.md`
2. Ratings calculated automatically for all IPOs with sufficient data
3. Dashboard IPO cards display star ratings (1-5)
4. IPO detail pages show rating with rationale breakdown
5. "Not yet rated" for new IPOs without enough data (not "Not Rated")

### 5. Registrar Information Display
1. Registrar name displayed on IPO detail pages
2. Registrar contact information (phone, email, website) shown
3. Link to registrar directory page at `/registrars`
4. Fallback to "To be announced" for IPOs without registrar assigned

### 6. Filter Functionality
1. Status filter (All, Open, Upcoming, Closed) works on Dashboard
2. Category filter (Mainboard, SME, NCD) works on Dashboard
3. Exchange filter (NSE, BSE, Both) works on Dashboard
4. "Clear Filters" button enables when filters applied and resets all
5. Filter state persists in URL query parameters for sharing

### 7. Loading States
1. Dashboard shows skeleton cards (12 cards) while loading IPOs
2. IPO detail page shows skeleton layout while loading
3. Search results show loading spinner during search
4. Subscription data shows loading indicator during refresh
5. Smooth transitions between loading and loaded states (300ms)

### 8. Missing Data Endpoints
1. `GET /api/ipos/{slug}/subscriptions/latest` endpoint created
2. `GET /api/ipos/{slug}/gmp/latest` endpoint created
3. `GET /api/ipos/{slug}/rating` endpoint created
4. `GET /api/registrars` endpoint created for registrar directory
5. All endpoints return proper JSON with error handling

## Risks & Mitigation

### Risk 1: Rating Algorithm Accuracy
- **Impact:** Inaccurate ratings mislead investors, damage reputation
- **Probability:** Medium (algorithm complexity, data quality)
- **Mitigation:**
  - Implement confidence scoring (show when rating is uncertain)
  - Use conservative weights (favor proven factors over speculative)
  - Display rating rationale for transparency
  - Add disclaimer: "Rating is algorithmic, not investment advice"
  - Test algorithm with historical IPOs (backtest accuracy)
- **Code Example:**
  ```typescript
  // Conservative rating: Lower rating if confidence is low
  if (confidence < 50) {
    return {
      rating: null,
      rationale: ["Insufficient data for reliable rating"],
      confidence: 0
    };
  }
  ```

### Risk 2: Missing GMP Data
- **Impact:** Users expect GMP for all IPOs, may be disappointed
- **Probability:** High (Chittorgarh scraper may not have data for all IPOs)
- **Mitigation:**
  - Clear messaging: "GMP data not yet available for this IPO"
  - Set expectations: "GMP typically available 2-3 days before listing"
  - Show GMP for similar IPOs (sector, size)
  - Add "Request GMP Updates" feature (email notifications)

### Risk 3: Performance Degradation with Real-Time Updates
- **Impact:** Dashboard slow to load with frequent API calls
- **Probability:** Medium (depends on user traffic, API performance)
- **Mitigation:**
  - Implement efficient caching (5-15 minute TTLs)
  - Use SWR/React Query for intelligent background refresh
  - Implement request coalescing (batch multiple requests)
  - Monitor API response times and optimize slow queries
  - Consider server-side rendering (SSR) for initial page load

### Risk 4: Database Schema Migration Failures
- **Impact:** Production deployment fails, site unavailable
- **Probability:** Low (with proper testing)
- **Mitigation:**
  - Test migrations in staging environment first
  - Create rollback migration for every forward migration
  - Backup database before running migrations
  - Use Drizzle Kit migration generation (automatic, safe)
  - Test application with new schema before deployment
- **Rollback Plan:**
  ```sql
  -- Rollback migration if needed
  ALTER TABLE ipos DROP COLUMN IF EXISTS rating;
  ALTER TABLE ipos DROP COLUMN IF EXISTS rating_rationale;
  ALTER TABLE ipos DROP COLUMN IF EXISTS rating_confidence;
  ALTER TABLE ipos DROP COLUMN IF EXISTS rating_updated_at;
  ```

### Risk 5: Incomplete Data Display (Null/Undefined Handling)
- **Impact:** UI shows errors, "undefined", or blank spaces
- **Probability:** High (scrapers may miss data for some IPOs)
- **Mitigation:**
  - Implement comprehensive null checks in all components
  - Use fallback values: "Not available", "To be announced", "Data pending"
  - Display helpful messages: "Subscription data will be available once IPO opens"
  - Test with incomplete data scenarios
  - Add PropTypes or TypeScript strict null checks
- **Code Example:**
  ```typescript
  // Null-safe subscription display
  const subscriptionDisplay = subscription
    ? `${subscription.total}x subscribed`
    : ipo.status === 'UPCOMING'
      ? 'Subscription data available after IPO opens'
      : 'No subscription data available';
  ```
