## Story
**As a** Rahul (active investor),
**I want** to compare 2-3 IPOs side-by-side in a detailed comparison table,
**so that** I can make informed investment decisions by evaluating multiple opportunities simultaneously.

## Acceptance Criteria
1. Standalone comparison page at `/tools/compare`
2. IPO selection interface supporting 2-3 IPOs (dropdown search)
3. Comparison table displaying:
   - Price range, lot size
   - Subscription status (QIB, NII, Retail, Total)
   - GMP (current value)
   - Financial metrics (P/E ratio, ROE, Revenue growth, EPS)
   - Rating (1-5 stars with rationale)
4. Shareable URL format: `/tools/compare?ipos=slug1,slug2,slug3`
5. Shareable URL pre-populates selected IPOs when accessed
6. "Add to Compare" button on IPO detail page
7. Support for adding/removing IPOs from comparison
8. Empty state when no IPOs selected
9. Mobile-responsive comparison table (horizontal scroll)
10. Data validation: Only allow active IPOs (OPEN, UPCOMING, CLOSED)
11. Error handling for invalid slugs or missing data
12. Loading states during data fetching
13. Export comparison as image (Phase 2 - document in Dev Notes)

### API Specifications

**Endpoint Details** [Source: docs/architecture/api-specification.md#tools-calculators]:
- Method: POST
- Path: `/api/tools/compare`
- Request Body: `{ ipoSlugs: string[] }` (2-3 slugs)
- Response: `{ comparisons: IPOComparison[], comparedAt: Date }`
- Cache TTL: No caching (comparison endpoint with dynamic inputs)
- Rate Limit: 100 requests/minute per IP

**Validation Rules**:
- Minimum 2 IPOs, maximum 3 IPOs
- Only valid slug format (lowercase, hyphen-separated)
- Only active IPO statuses: OPEN, UPCOMING, CLOSED

**Error Responses**:
- 400 Bad Request: Invalid slug format or count
- 404 Not Found: One or more IPOs not found
- 500 Internal Server Error: Database or repository errors

### URL State Management

**Shareable URL Format** [Source: docs/stories/epics/epic-5-ipo-tools.md#52-ipo-comparison-tool]:
- Format: `/tools/compare?ipos=slug1,slug2,slug3`
- Parse query params on page load to pre-populate selection
- Update URL when selection changes (without page reload)
- Use Next.js `useRouter` and `useSearchParams` hooks

**Implementation Pattern**:
```typescript
// Parse URL params
const searchParams = useSearchParams();
const slugsFromUrl = searchParams.get('ipos')?.split(',') || [];

// Update URL on selection change
const router = useRouter();
router.push(`/tools/compare?ipos=${selectedSlugs.join(',')}`);
```

### Session Storage

**Persistent Selection** [Source: AC #6]:
- Store selected IPO slugs in session storage
- Persist selection across page navigation
- Retrieve selection when returning to comparison page
- Clear selection on explicit user action (Clear All button)

**Implementation Pattern**:
```typescript
// Save to session storage
sessionStorage.setItem('comparisonIPOs', JSON.stringify(selectedSlugs));

// Retrieve from session storage
const savedSlugs = JSON.parse(sessionStorage.getItem('comparisonIPOs') || '[]');
```
