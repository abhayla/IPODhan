# Story 12.2: Fix Lot Size Validation and Cool Caps Lot Size

## Status
**Ready** - Critical Priority (P0)

## Story
**As a** IPO investor,
**I want** accurate lot sizes for all IPOs (never 1 share),
**so that** I can calculate correct investment amounts and application quantities.

## Problem Statement
Cool Caps Industries Limited shows **lot_size = 1 share** on IPODhan, but NSE shows **3000 shares per lot**. This is a **CRITICAL** error identified in Phase 3:
- LOT_SIZE_EXECUTIVE_SUMMARY.md documents that 68.89% of IPOs had lot_size = 1
- Lot size validation was supposed to prevent this (Phase 3 enhancement)
- Investment calculations will be completely wrong
- Users cannot apply correctly

**Evidence**:
- NSE: "Market Lot: 3000 Equity Shares and in multiples thereof"
- IPODhan: "Lot Size: 1 shares"

## Acceptance Criteria
1. Cool Caps lot_size must be corrected to 3000 (not 1)
2. Database constraint must prevent lot_size = 1 for any IPO
3. Scraper must extract lot size from NSE "Market Lot" field
4. Scraper validation utility must reject lot_size = 1 before DB insert
5. UI must display lot size with proper formatting: "3,000 shares" not "1 shares"
6. Lot calculator tool must use correct lot size for calculations
7. All existing IPOs with lot_size = 1 must be identified and flagged for re-scraping
8. Migration script must fix known incorrect lot sizes

### Validation Utility Pattern
```typescript
// scraper/src/utils/validators.ts
export function validateLotSize(lotSize: number | null): boolean {
  if (lotSize === null) return true;  // Not available yet - OK
  if (lotSize === 1) return false;     // Invalid - REJECT
  return lotSize > 1;                  // Valid
}

// Usage in scraper
if (!validateLotSize(ipoData.lot_size)) {
  logger.warn(`Invalid lot_size=${ipoData.lot_size} for ${ipoData.companyName}, skipping`);
  return null; // Don't insert
}
```
