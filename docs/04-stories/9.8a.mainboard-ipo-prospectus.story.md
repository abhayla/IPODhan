# Story 9.8a: Mainboard IPO Prospectus PDF Download Page

## Status
Done (Implemented 2025-10-13)

## Story

**As a** investor interested in Mainboard IPO due diligence,
**I want** to access a comprehensive page to download Draft Red Herring Prospectus (DRHP) and Red Herring Prospectus (RHP) documents for Mainboard IPOs,
**so that** I can review official Mainboard IPO documents for research and analysis before making investment decisions.

## Acceptance Criteria

1. Mainboard Prospectus page accessible at `/mainboard-ipo-prospectus`
2. Table displays all 4 columns with correct Mainboard IPO data only
3. Total records count displays (e.g., "Total Records: 847")
4. Column-level search boxes functional:
   - Company Name search filters results
   - Exchange filter works (All, BSE, NSE, Both)
5. Sortable columns work correctly (Company Name, Exchange)
6. Company name links navigate to respective IPO detail pages
7. DRHP and RHP PDF links are functional:
   - Links open in new tab (`target="_blank"`)
   - External link icon displayed
   - Download attribute set for direct download
8. Search results update in real-time (debounced 300ms)
9. Empty state shows "No Mainboard prospectus documents available" message
10. Loading skeleton displays during data fetch
11. Page uses ISR with 10-minute revalidation
12. Responsive: table on desktop, cards/list on mobile
13. Pagination works correctly (50 records per page)
14. SEO metadata configured (title, description, keywords)
15. Navigation link added to "Mainboard IPOs" submenu
16. Only Mainboard IPOs displayed (filter: category=MAINBOARD)
17. PDF download links handle missing documents gracefully (show "-" or "Not Available")

### Component Architecture

**Server vs Client Components**:
- **Page Component** (`page.tsx`): Server component
  - SEO metadata export
  - ISR configuration
  - Initial page structure
- **Client Wrapper** (`MainboardProspectusClient.tsx`): Client component
  - Filter state management
  - URL synchronization
  - Data fetching orchestration
  - Client-side sorting
- **Table Component** (`MainboardProspectusTable.tsx`): Client component
  - Pure presentation with sorting
  - Desktop table and mobile cards
  - Loading/empty states
- **Column Search** (`ColumnSearch.tsx`): Client component
  - Text input with debouncing
  - Select dropdown
  - Reusable across columns

**State Management Strategy**:
- **Filter State**: URL query params (shareable URLs)
  - Default: `/mainboard-ipo-prospectus`
  - With filters: `/mainboard-ipo-prospectus?company=abc&exchange=BSE&page=2`
- **Sorting State**: Client-side only (ephemeral)
- **Loading State**: Client state (during data fetching)

### Technical Decisions

**Decision 1: No API Endpoint Created**
- **Decision**: Use service layer directly, no dedicated API endpoint
- **Rationale**:
  - Simpler architecture (fewer files)
  - Service layer can use Drizzle ORM directly
  - No need for REST API overhead
  - Better type safety

**Decision 2: Client-Side Sorting**
- **Decision**: Sort data on client after fetching
- **Rationale**:
  - Instant sorting response (no server round-trip)
  - Data set is manageable size (50 records per page)
  - Better UX (immediate feedback)
  - Reduces server load

**Decision 3: URL-Based Filters**
- **Decision**: Store filters in URL query params
- **Rationale**:
  - Shareable URLs (bookmarkable)
  - Browser back/forward works correctly
  - SEO-friendly (different URLs for different filters)
  - Server can read state (SSR compatibility)

**Decision 4: 10-Minute ISR for Documents**
- **Decision**: Use 10-minute ISR revalidation (longer than performance tracker)
- **Rationale**:
  - Document URLs change infrequently
  - Balance freshness vs performance
  - Reduces database load
  - Still provides reasonably fresh data

**Decision 5: Drizzle ORM Direct Queries**
- **Decision**: Use Drizzle ORM for database queries in service layer
- **Rationale**:
  - Type-safe queries
  - Better performance (no REST overhead)
  - Simpler architecture
  - JOIN support

### Database Schema Requirements

**Documents Table**:
```sql
CREATE TABLE documents (
  id TEXT PRIMARY KEY,
  ipo_id TEXT NOT NULL REFERENCES ipos(id),
  document_type TEXT NOT NULL, -- 'DRHP', 'RHP', 'PROSPECTUS', 'OTHER'
  document_url TEXT NOT NULL,
  upload_date TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
  CONSTRAINT fk_ipo FOREIGN KEY (ipo_id) REFERENCES ipos(id)
);

CREATE INDEX idx_documents_ipo_id ON documents(ipo_id);
CREATE INDEX idx_documents_type ON documents(document_type);
```

**IPOs Table** (existing):
- `category` column includes 'MAINBOARD'
- `listingExchanges` JSONB array field: `['BSE']`, `['NSE']`, or `['BSE', 'NSE']`
