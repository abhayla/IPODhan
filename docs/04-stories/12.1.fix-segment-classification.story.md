# Story 12.1: Fix IPO Segment Classification (SME vs MAINBOARD)

## Status
**Ready** - Critical Priority (P0)

## Dependencies
- **Related**: Story 11.8 (Category → Segment+OfferingType Restructure) - COMPLETED

## Story
**As a** IPO investor,
**I want** IPOs to have their **segment field** correctly set as SME or MAINBOARD based on NSE/BSE data,
**so that** I can filter and view IPOs in the correct segment and make informed investment decisions.

## Problem Statement
Cool Caps Industries Limited is classified as **MAINBOARD** on IPODhan but is actually an **SME IPO** on NSE. This causes:
- Incorrect filtering (SME investors won't find it)
- Wrong data segregation (Phase 4 category isolation violated)
- Misleading investment information

**Evidence**: NSE shows "Series: EQ" and "SME" segment, IPODhan shows "MAINBOARD"

## Acceptance Criteria

**Critical (Must Pass):**
1. All IPOs scraped from NSE SME platform must have `segment = 'SME'` in database
2. All IPOs scraped from NSE Mainboard must have `segment = 'MAINBOARD'` in database
3. Cool Caps Industries Limited must show as "SME" not "MAINBOARD" on UI
4. SME IPO page (`/sme-ipos`) must display Cool Caps correctly
5. Mainboard IPO page (`/mainboard-ipos`) must NOT display Cool Caps
6. Database query filters by `segment` field must work correctly
7. API endpoints must respect segment filtering (no cross-contamination)

**Optional (Nice to Have):**
8. Symbol suffix logic: NSE symbols should match exactly as provided by NSE (no suffix modifications like 'R') - *(Separate bug, bonus fix if time permits)*

### Database Field Info
- Table: `ipos`
- Field: `segment` (nullable enum: 'MAINBOARD' | 'SME' | null)
- Purpose: Supports RIGHTS/InvITs/REITs offerings (which use null)
- UI Display: Use null coalescing: `{ipo.segment || 'N/A'}`

### NSE API Detection Logic
- SME IPOs: URL contains `/sme/` or query param `series=SME`
- Mainboard IPOs: URL contains `/mainboard/` or `series=EQ` (without SME context)
- Example: `?symbol=COOLCAPS&series=SME&type=Past` → segment='SME'
