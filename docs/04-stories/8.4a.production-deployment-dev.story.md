## Dev Notes

### Architecture Context
This story prepares the local development environment with all necessary configuration files, scripts, and documentation needed for production deployment to Windows VPS (103.118.16.189).

[Source: architecture/deployment-architecture.md]

### Deployment Architecture

**Target Platform:**
- Windows Server 2022 VPS at IP: 103.118.16.189
- Node.js 20 LTS runtime
- PM2 5.3+ for process management
- Cloudflare CDN for static assets and SSL

**Applications:**
1. **ipodhan-web:** Next.js 14.2+ application (2 instances, cluster mode)
2. **ipodhan-scraper:** Data scraping service (1 instance, fork mode, cron: 3 AM daily)

[Source: architecture/deployment-architecture.md#deployment-strategy]

### Health Check Endpoint

The `/api/health` endpoint should:
- Check PostgreSQL connection using a simple query
- Check Redis connection using PING command
- Return 200 OK if all services healthy
- Return 503 Service Unavailable if any service down
- Include timestamp for monitoring

[Source: architecture/monitoring-and-observability.md#health-check-endpoint]

### Environment Variables

Critical production environment variables:
- `DATABASE_URL`: PostgreSQL connection string
- `REDIS_URL`: Redis connection string
- `NODE_ENV`: Must be "production"
- `NEXTAUTH_SECRET`: Random secret for session encryption
- `NEXT_PUBLIC_API_URL`: Public API URL (https://ipodhan.com/api)

[Source: architecture/deployment-architecture.md#environments]

### PM2 Configuration

PM2 ecosystem.config.js provides:
- Process management for web and scraper apps
- Cluster mode for web (2 instances for load balancing)
- Fork mode for scraper (single instance)
- Auto-restart on crash
- Memory limits (500M web, 300M scraper)
- Log management with rotation
- Cron restart for scraper (daily at 3 AM)

[Source: architecture/deployment-architecture.md#pm2-configuration]

### Deployment Package

The deployment package script creates a portable archive containing:
- Web app: Built .next/ output + dependencies
- Scraper: Compiled dist/ output + dependencies
- Configuration: ecosystem.config.js
- Ready to extract and run on VPS

[Source: architecture/deployment-architecture.md#cicd-pipeline]

### Security Considerations

**Critical Security Rules:**
- NEVER commit `.env.production` to Git
- Store sensitive credentials only on server
- Use strong database passwords
- Restrict .env.production file permissions (chmod 600 on server)
- Generate random NEXTAUTH_SECRET on server

[Source: architecture/security-and-performance.md#security-requirements]

### Testing
