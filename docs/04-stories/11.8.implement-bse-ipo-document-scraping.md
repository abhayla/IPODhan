## Story

**As a** IPO investor,
**I want** access to all IPO documents (DRHP, RHP, Prospectus, Basis of Allotment, and Audiovisual variants) from BSE,
**so that** I can perform due diligence and make informed investment decisions with complete regulatory information.

---

## Business Value

### Current Gap
- Database has `documents` table but NO scraper populates it
- BSE provides 6+ document types per IPO, but none are captured
- Investors cannot access critical regulatory documents from the platform
- Competitive disadvantage vs. platforms that provide document links

### Expected Outcome
- All BSE document links automatically scraped and stored
- Investors can access DRHP, RHP, Prospectus, and other documents
- Support for both PDF and Audiovisual (video) formats
- Comprehensive document library for each IPO

## Acceptance Criteria

### AC1: Database Schema Enhancement
- **Given** the existing `documents` table structure
- **When** schema is updated
- **Then**:
  - Add `mediaType` VARCHAR(20) field with default 'PDF'
  - Add `sequenceNumber` INTEGER field with default 1
  - Add `isActive` BOOLEAN field with default true
  - Update `documentTypeEnum` to include 'BASIS_OF_ALLOTMENT'
  - Add composite unique constraint on (ipoId, type, mediaType, exchange, sequenceNumber)
  - Maintain URL unique constraint globally
  - Generate and apply migration successfully

### AC2: BSE Document Link Extraction
- **Given** a BSE IPO detail page URL
- **When** scraper processes the page
- **Then**:
  - Extract all document links from the detail page
  - Identify document type (DRHP, RHP, PROSPECTUS, BASIS_OF_ALLOTMENT, ADDENDUM)
  - Identify media type (PDF vs VIDEO)
  - Extract document title
  - Extract document URL
  - Handle missing documents gracefully (some IPOs may not have all types)

### AC3: Document Type Detection
- **Given** a document link and title from BSE
- **When** document type detection runs
- **Then**:
  - "Draft Red Herring Prospectus" → type=DRHP, mediaType=PDF
  - "Audiovisual DRHP" → type=DRHP, mediaType=VIDEO
  - "Red Herring Prospectus" → type=RHP, mediaType=PDF
  - "Audiovisual RHP" → type=RHP, mediaType=VIDEO
  - "Prospectus" → type=PROSPECTUS, mediaType=PDF
  - "Basis of allotment" → type=BASIS_OF_ALLOTMENT, mediaType=PDF
  - "Addendum" / "Corrigendum" → type=ADDENDUM, mediaType=PDF
  - Multiple addendums → sequenceNumber increments (1, 2, 3...)

### AC4: Upsert Logic (Prevent Duplicates)
- **Given** a document that may already exist in database
- **When** scraper attempts to save document
- **Then**:
  - If same URL exists → Update updatedAt timestamp, set isActive=true
  - If same (ipoId + type + mediaType + exchange) with different URL → Increment sequenceNumber
  - No duplicate constraint violations occur
  - Old documents can be marked inactive when superseded

### AC5: Integration with BSE Scraper
- **Given** BSE scraper is running
- **When** processing each IPO detail page
- **Then**:
  - Document scraping happens after detail page data extraction
  - Documents are associated with correct IPO via ipoId
  - Exchange field is set to 'BSE'
  - Errors in document scraping don't fail the entire IPO scrape
  - Document scraping errors are logged but non-blocking

### AC6: Data Validation & Storage
- **Given** scraped document data
- **When** storing to database
- **Then**:
  - All required fields populated (ipoId, type, title, url, exchange)
  - URLs are valid and absolute
  - MediaType is either 'PDF' or 'VIDEO'
  - Timestamps (createdAt, updatedAt) set correctly
  - Documents queryable by IPO
  - Documents filterable by type and mediaType

### AC7: Testing & Quality
- **Given** the document scraping feature
- **When** comprehensive tests run
- **Then**:
  - Unit tests cover document type detection (15+ test cases)
  - Unit tests cover upsert logic (10+ test cases)
  - Integration test with real BSE detail page succeeds
  - Test coverage ≥ 80% for new code
  - No regressions to existing BSE scraper functionality
  - All tests passing (100% pass rate)

## Technical Design

### Database Schema Changes

```typescript
// packages/shared/src/db/schema.ts

export const documentTypeEnum = pgEnum('document_type', [
  'DRHP',                    // Draft Red Herring Prospectus
  'RHP',                     // Red Herring Prospectus
  'PROSPECTUS',              // Final Prospectus
  'BASIS_OF_ALLOTMENT',      // NEW: Basis of Allotment Advertisement
  'ADDENDUM',                // Addendum/Corrigendum
]);

export const documents = pgTable(
  'documents',
  {
    id: uuid('id').primaryKey().defaultRandom(),
    ipoId: uuid('ipo_id').notNull().references(() => ipos.id, { onDelete: 'cascade' }),
    type: documentTypeEnum('type').notNull(),

    // NEW FIELDS
    mediaType: varchar('media_type', { length: 20 }).default('PDF').notNull(), // 'PDF' or 'VIDEO'
    sequenceNumber: integer('sequence_number').default(1).notNull(), // For multiple documents of same type
    isActive: boolean('is_active').default(true).notNull(), // Track superseded documents

    title: varchar('title', { length: 255 }).notNull(),
    url: text('url').notNull(),
    fileSize: bigint('file_size', { mode: 'number' }),
    uploadedAt: timestamp('uploaded_at').defaultNow().notNull(),
    exchange: varchar('exchange', { length: 10 }), // 'NSE' | 'BSE'
    createdAt: timestamp('created_at').defaultNow().notNull(),
    updatedAt: timestamp('updated_at').defaultNow().notNull(),
  },
  (table) => ({
    exchangeIdx: index('idx_documents_exchange').on(table.exchange),

    // NEW: Composite unique constraint
    uniqueDocPerIpo: unique('unique_doc_per_ipo').on(
      table.ipoId,
      table.type,
      table.mediaType,
      table.exchange,
      table.sequenceNumber
    ),

    // Keep URL unique globally
    uniqueUrl: unique('unique_url').on(table.url),
  })
);
```

### Document Scraping Flow

```
1. BSE Scraper fetches detail page HTML
   ↓
2. Extract IPO details (existing logic)
   ↓
3. **NEW** Extract document links from same HTML
   ↓
4. For each document link:
   - Detect type (DRHP, RHP, etc.)
   - Detect mediaType (PDF vs VIDEO)
   - Determine sequenceNumber
   ↓
5. Batch upsert documents to database
   - If URL exists → Update timestamp
   - If new document of existing type → Increment sequence
   - If new type → Sequence starts at 1
   ↓
6. Log document counts and continue
```

- Scraper updates existing records instead of failing
- Always have latest document URL
- Support for multiple documents of same type (addendums)
