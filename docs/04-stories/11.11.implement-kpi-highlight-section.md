## Business Context

### Problem Statement
Currently, critical financial metrics (KPIs) are **scattered across the IPO detail page** with only **40% coverage** of key investor metrics. There is no dedicated, visually prominent section for quick investor decision-making. This creates a poor user experience compared to competitors like Chittorgarh who display KPIs in a dedicated, easy-to-scan section.

### Business Value
- **Investor Experience**: Quick access to critical financial metrics in one location
- **Competitive Parity**: Match Chittorgarh's KPI section presentation
- **Decision Support**: Help investors make faster, better-informed decisions
- **Professional UI**: Elevate platform credibility with comprehensive financial data display

### User Impact
**Who benefits:**
- Retail investors evaluating IPO investment decisions
- Research analysts comparing multiple IPOs
- Financial advisors seeking quick metric snapshots

**User Journey:**
1. User lands on IPO detail page
2. User sees prominent KPI section near top (below header/key metrics)
3. User quickly scans 6-8 critical financial metrics with icons
4. User hovers over metrics to see tooltip explanations
5. User compares Pre-IPO vs Post-IPO EPS and P/E ratios
6. User makes informed investment decision faster

## Technical Requirements

### Database Schema Changes

**Table:** `financial_data`

**New Columns to Add:**
```sql

ALTER TABLE financial_data
ADD COLUMN market_cap NUMERIC(15,2),  -- Market capitalization in crores

ADD COLUMN post_ipo_eps NUMERIC(10,2),  -- Post-IPO Earnings Per Share
ADD COLUMN ronw NUMERIC(5,2);  -- Return on Net Worth %

COMMENT ON COLUMN financial_data.market_cap IS 'Market capitalization in ₹ crores (Post-issue shares × Issue price)';
COMMENT ON COLUMN financial_data.pre_ipo_eps IS 'Pre-IPO Earnings Per Share';
COMMENT ON COLUMN financial_data.post_ipo_eps IS 'Post-IPO Earnings Per Share';
COMMENT ON COLUMN financial_data.ronw IS 'Return on Net Worth percentage';
```

**Existing Fields (Already in DB):**
- `roe` - Return on Equity %
- `price_to_book` or `pb_ratio` - Price-to-Book Value ratio

### Data Calculations

**Formula Definitions:**

1. **Market Capitalization**
   ```
   Market Cap = Post-issue shares × Issue price
   ```
   - Example: 10,000,000 shares × ₹500 = ₹5,000 crores
   - Display format: "₹5,000 Cr"

2. **Return on Equity (ROE)**
   ```
   ROE = (Net Profit / Shareholders' Equity) × 100
   ```
   - Already in database
   - Display format: "18.5%"

3. **Return on Net Worth (RoNW)**
   ```
   RoNW = (Net Profit / Net Worth) × 100
   ```
   - Calculate and store in `ronw` field
   - Display format: "22.3%"

4. **Price-to-Book Value (P/BV)**
   ```
   P/BV = Market Price per Share / Book Value per Share
   ```
   - Already in database as `price_to_book` or `pb_ratio`
   - Display format: "3.2x"

5. **Pre-IPO EPS**
   ```
   Pre-IPO EPS = Annual Profit / Pre-issue Outstanding Shares
   ```
   - Calculate and store in `pre_ipo_eps`
   - Display format: "₹45.20"

6. **Post-IPO EPS**
   ```
   Post-IPO EPS = Annual Profit / Post-issue Outstanding Shares
   ```
   - Calculate and store in `post_ipo_eps`
   - Display format: "₹38.50"

7. **Pre-IPO P/E Ratio**
   ```
   Pre-IPO P/E = (Issue Price × Pre-issue Shares) / Annual Profit
   ```
   - Calculate on frontend from pre_ipo_eps
   - Display format: "25.5x"

8. **Post-IPO P/E Ratio**
   ```
   Post-IPO P/E = (Issue Price × Post-issue Shares) / Annual Profit
   ```
   - Calculate on frontend from post_ipo_eps
   - Display format: "30.2x"

### Frontend Component

**Component Name:** `KPIHighlightSection.tsx`

**Location:** `web/components/ipo-detail/KPIHighlightSection.tsx`

**Component Structure:**
```typescript
interface KPIHighlightSectionProps {
  financialData: {
    market_cap: number | null;
    roe: number | null;
    ronw: number | null;
    price_to_book: number | null;
    pre_ipo_eps: number | null;
    post_ipo_eps: number | null;
  };
  ipoData: {
    issuePrice: number;
    preIssueShares: number;
    postIssueShares: number;
    annualProfit: number;
  };
}

export function KPIHighlightSection({ financialData, ipoData }: KPIHighlightSectionProps) {
  // Calculate derived metrics
  const preIpoPE = calculatePreIPO_PE(ipoData);
  const postIpoPE = calculatePostIPO_PE(ipoData);
  const epsChange = calculateEPSChange(financialData);
  const peChange = calculatePEChange(preIpoPE, postIpoPE);

  return (
    <section className="kpi-highlight-section">
      <h2>Key Performance Indicators</h2>
      <div className="kpi-grid">
        <KPICard
          icon={<MarketCapIcon />}
          title="Market Capitalization"
          value={formatMarketCap(financialData.market_cap)}
          tooltip="Post-IPO market capitalization based on issue price"
        />
        <KPICard
          icon={<ROEIcon />}
          title="ROE"
          value={formatPercentage(financialData.roe)}
          tooltip="Return on Equity - measures profitability relative to shareholder equity"
        />
        <KPICard
          icon={<RoNWIcon />}
          title="RoNW"
          value={formatPercentage(financialData.ronw)}
          tooltip="Return on Net Worth - net profit as percentage of net worth"
        />
        <KPICard
          icon={<PBIcon />}
          title="Price-to-Book"
          value={formatRatio(financialData.price_to_book)}
          tooltip="Price-to-Book Value ratio - market price relative to book value"
        />
        <KPIComparisonCard
          icon={<EPSIcon />}
          title="EPS (Pre vs Post)"
          preValue={formatCurrency(financialData.pre_ipo_eps)}
          postValue={formatCurrency(financialData.post_ipo_eps)}
          change={epsChange}
          tooltip="Earnings Per Share comparison before and after IPO"
        />
        <KPIComparisonCard
          icon={<PEIcon />}
          title="P/E Ratio (Pre vs Post)"
          preValue={formatRatio(preIpoPE)}
          postValue={formatRatio(postIpoPE)}
          change={peChange}
          tooltip="Price-to-Earnings ratio comparison before and after IPO"
        />
      </div>
    </section>
  );
}
```

**UI Design Specifications:**
- **Layout**: Grid layout (3 columns on desktop, 2 on tablet, 1 on mobile)
- **Card Design**:
  - White background with subtle border
  - Icon on left (use lucide-react icons)
  - Metric name and value on right
  - Tooltip trigger on hover/click
- **Color Coding**:
  - Green text/icon for positive changes (EPS increase, low P/E)
  - Red text/icon for negative changes (EPS decrease, high P/E)
  - Neutral gray for standalone metrics
- **Typography**:
  - Metric name: text-sm, font-medium, text-gray-600
  - Metric value: text-2xl, font-bold, text-gray-900
  - Comparison change: text-sm, font-semibold, color-coded
- **Placement**: Below "Key Metrics" card or as second prominent section after header

## Risks & Mitigation

### Risk 1: Missing Financial Data
**Risk:** Many IPOs may not have complete KPI data (market_cap, EPS, etc.)
**Impact:** KPI section may show many "N/A" values, poor UX
**Mitigation:**
- Implement graceful degradation: Hide KPI cards with missing data
- Show partial KPI section if at least 3 metrics available
- Add data completeness indicator ("4 of 6 metrics available")
- Prioritize scraper enhancement to populate missing fields

**Contingency:** If >50% of IPOs have missing data, de-prioritize feature or phase rollout

---

### Risk 2: Calculation Errors
**Risk:** Incorrect KPI calculations mislead investors
**Impact:** Reputational damage, loss of user trust
**Mitigation:**
- Write comprehensive unit tests for all calculation functions
- Cross-validate calculations with competitor sites (Chittorgarh)
- Manual QA verification on 10 sample IPOs
- Add calculation formula documentation
- Include data source attribution ("Calculated from DRHP")

**Contingency:** If calculation errors found in production, add disclaimer and fix immediately

---

### Risk 3: Performance Impact
**Risk:** Adding KPI section increases page load time
**Impact:** Poor user experience, higher bounce rate
**Mitigation:**
- Use caching aggressively (15-min TTL for financial data)
- Fetch financial data in parallel with other IPO data
- Optimize database queries (select only required fields)
- Implement code splitting (lazy load KPI section if needed)
- Monitor performance with Lighthouse

**Contingency:** If page load time exceeds 3s, implement lazy loading or move KPI to separate tab

---

### Risk 4: Design Complexity
**Risk:** KPI section looks cluttered or overwhelming on mobile
**Impact:** Poor mobile UX, low engagement
**Mitigation:**
- Design mobile-first (1 column grid on mobile)
- Use icons to reduce text clutter
- Implement collapsible sections on mobile if needed
- Test on real mobile devices (not just browser emulation)
- User testing with 3-5 investors

**Contingency:** If mobile UX poor, create simplified mobile view or hide some KPIs on small screens
