## Business Context

### Problem Statement
The IPO Detail page currently lacks a dedicated Category-wise Reservation Details section that shows exact allocation percentages and share counts per investor category. This information is critical for investors to understand how IPO shares are distributed across different investor categories (QIB, NII, Retail, Employee, Anchor).

**Current State:** 0% implemented - no category reservation display exists
**Competitive Gap:** Chittorgarh.com displays this information prominently
**Data Availability:** Reservation percentages already exist in database (`ipo_details` table)

### User Value
**Primary User Persona:** Retail investors seeking comprehensive IPO information

**Key Benefits:**
1. **Transparency**: Clear visibility into how shares are allocated across categories
2. **Investment Planning**: Helps investors understand their category's allocation
3. **Competitive Parity**: Matches feature set of leading IPO platforms like Chittorgarh
4. **Data Completeness**: Leverages existing database fields with minimal additional data requirements

### Business Impact
- **Feature Coverage**: Increases IPO detail page completeness from 62% to ~65% (vs Chittorgarh)
- **User Trust**: Demonstrates comprehensive IPO data coverage
- **Implementation Effort**: Low (1 day) - data already exists, mostly UI work
- **ROI**: High value for minimal effort

### Data Flow

**Data Sources:**
1. **Primary:** `ipo_details` table (existing percentages + new share counts)
2. **Fallback Calculation:** Calculate share counts from percentages if not available:
   - `qib_shares_offered = total_issue_shares × (qib_reservation / 100)`
   - Same formula for other categories

**Repository Pattern:**
```typescript
// IPODetailsRepository.ts
async findByIPOId(ipoId: string): Promise<IPODetails | null> {
  const cacheKey = getIPODetailsByIdKey(ipoId);

  return this.getFromCache(cacheKey, async () => {
    const result = await this.db.select().from(ipoDetails)
      .where(eq(ipoDetails.ipoId, ipoId));
    return result[0] || null;
  }, CacheTTL.IPO_DETAIL); // 15 minutes
}
```

**Service Layer:** No new service required - use existing `IPODetailsRepository`

**Cache Strategy:**
- Cache Key: `ipo-details:ipo-id:{ipoId}`
- TTL: 15 minutes (static data, rarely changes)
- Invalidation: On `ipoDetails` update (via scraper)
