## Story
**As a** Priya (newcomer investor),
**I want** to access a comprehensive directory of IPO registrars with their contact information,
**so that** I can quickly find registrar details to check allotment status or resolve IPO-related queries.

## Acceptance Criteria
1. Dedicated Registrar Directory page at `/registrars`
2. Display registrars in alphabetical order
3. Show: name, email, phone, website, allotment link for each
4. Search bar filters by registrar name
5. Responsive: Table on desktop, cards on mobile
6. Database table `registrars` with 10-15 seed entries
7. Integration with IPO detail page (linked from allotment checker)
8. Clickable website URLs open in new tab
9. Loading states and error handling
10. Accessible from "Tools" menu in navigation

### Data Models
**Registrar Interface** [Source: docs/architecture/data-models.md#registrar-mvp]:
```typescript
export interface Registrar {
  id: string;                    // UUID
  name: string;                  // e.g., "Link Intime India Pvt Ltd"
  shortName: string;             // e.g., "Link Intime"
  email: string;                 // Contact email for IPO queries
  phone: string | null;
  website: string;
  allotmentCheckUrl: string | null; // URL pattern for allotment status
  address: string | null;
  logoUrl: string | null;
  active: boolean;               // Is registrar currently active?
  createdAt: Date;
  updatedAt: Date;
}
```

**Database Schema** [Source: docs/architecture/data-models.md#registrar-mvp]:
- Table: `registrars`
- Primary Key: `id` (UUID)
- Indexes: `idx_registrars_name` (for alphabetical ordering), `idx_registrars_active` (for filtering active registrars)
- Unique Constraint: `name` (no duplicate registrar names)

### API Specifications
**Endpoint Details** [Source: docs/architecture/api-specification.md#registrar-directory-mvp]:
- Method: GET
- Path: `/api/registrars`
- Query Params: `search` (optional) - Filter by registrar name
- Response Type: `Registrar[]`
- Cache TTL: 7 days (ISR revalidation)
- Rate Limit: 100 requests/minute per IP

**Performance Considerations** [Source: docs/epics/epic-5-sharded.md#success-criteria]:
- Page load time: <1.5 seconds
- Search filtering: Real-time (debounced 300ms)
- Use ISR for static page generation with 7-day revalidation
- Redis caching to reduce database load

**Security Considerations**:
- All external links must use `target="_blank"` with `rel="noopener noreferrer"`

### Caching Strategy
**Cache-Aside Pattern** [Source: docs/architecture/api-specification.md#caching-strategy]:
- Redis cache TTL: 7 days (604800 seconds)
- Cache keys:
  - All registrars: `registrars:all`
  - Search results: `registrars:search:{query}`
  - Individual registrar: `registrars:{id}`
- Cache invalidation: Manual (admin interface in Phase 2)
