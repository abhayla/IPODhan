## Story

**As a** IPODhan platform administrator,
**I want** the NSE scraper to successfully collect real-time subscription data for OPEN IPOs,
**so that** users can track live subscription figures (QIB, NII, Retail) and make informed investment decisions.

## Context

**Current Issue**: Subscription data collection is completely broken (0% coverage)
- **Subscription coverage**: 0 out of 37 OPEN IPOs have data (0%)
- **NSE API**: Returns 401 Unauthorized errors
- **Browser fallback**: Finds 0 IPOs (selector/tab navigation issues)
- **Business impact**: Real-time subscription tracking (core differentiator) is non-functional

**Root Cause**: NSE anti-bot detection triggered by insufficient authentication
- Only 1-2 cookies obtained (need 4+: nsit, nseappid, bm_sv, ak_bmsc)
- Missing required headers (Referer, Accept-Encoding, Sec-Fetch-*)
- No delay between requests (bot-like behavior)
- Wrong endpoint priority (using bulk endpoint instead of detailed subscription endpoint)

**Technical Errors**:
```
Error: NSE API returned 401 Unauthorized
Error: read ECONNRESET (connection closed by NSE server)
Logs: "NSE API returned auth error, refreshing session cookies"
```

**Goal**: Restore NSE subscription data collection to 100% for OPEN IPOs (37/37)

**Database Schema** [Source: architecture/database-schema.md]
- **subscriptions** table structure:
  - `id` (UUID primary key)
  - `ipo_id` (UUID foreign key → ipos.id)
  - `timestamp` (timestamptz - current time)
  - `qib_subscription` (numeric - QIB times subscribed)
  - `nii_subscription` (numeric - NII times subscribed)
  - `retail_subscription` (numeric - Retail times subscribed)
  - `total_subscription` (numeric - Total times subscribed)
  - `employee_subscription` (numeric, optional)
  - `anchor_subscription` (numeric, optional)
  - `bnii_subscription` (numeric, optional)
  - `snii_subscription` (numeric, optional)
  - `created_at` (timestamptz - auto)
- Index: `idx_subscriptions_ipo_timestamp` for efficient queries

**Backend Architecture** [Source: architecture/backend-architecture.md]
- **Repository Pattern**: SubscriptionRepository with cache-aside pattern
  - `findByIPO(ipoId)` - Get subscription history
  - `findLatest(ipoId)` - Get latest snapshot
  - `createSnapshot(ipoId, data)` - Insert new subscription data
- **Cache Strategy**: Check Redis before PostgreSQL, populate on miss with TTL
- **Connection Pooling**: Max 20 connections, idle timeout 30s

**Coding Standards** [Source: architecture/coding-standards.md]
- **Database Queries**: Always use Repository layer (never raw SQL)
- **Input Validation**: Validate with Zod schemas before persistence
- **Error Handling**: All scrapers use structured error logging with full context
- **Cache Invalidation**: Explicit Redis key deletion on data updates
- **Naming**: snake_case for database tables/fields, camelCase for TypeScript

**Technical Constraints**:
- **NSE Website**: Uses aggressive bot detection (Akamai Bot Manager)
- **Required Cookies**: nsit, nseappid, bm_sv, ak_bmsc (obtained from multi-page visit)
- **Required Headers**: Referer, Accept-Encoding, Sec-Fetch-* (browser fingerprinting)
- **Rate Limiting**: NSE may block IPs with too many rapid requests (use 1-2 second delays)
- **Windows Server**: VPS deployment requires Windows-compatible scripts

**API Endpoints** (NSE):
1. `/api/ipo-current-issue` - PRIMARY (detailed subscription breakdown by category)
2. `/json/liveMarket/live-upcoming-issues.json` - SECONDARY (may have less auth requirements)
3. `/api/all-upcoming-issues?category=ipo` - FALLBACK (bulk data, less detail)

  noOfTime: number;  // Times subscribed (QIB/NII/Retail/Total)
  category: "QIB" | "NII" | "Retail" | "Total" | "Employee" | "Anchor";
}
