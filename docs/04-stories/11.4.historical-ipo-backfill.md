## Story Statement

**As a** platform administrator
**I want** to backfill historical IPO data from NSE past endpoints
**So that** our database contains comprehensive listing performance and historical IPO information for analysis and display.

---

## Business Context

### Problem Statement
Our database lacks comprehensive historical IPO data, particularly listing performance metrics (listing gains, current prices) and past IPO information. NSE provides two dedicated endpoints for past IPO data that we're not currently utilizing:
- `/api/public-past-issues` - Historical IPOs with listing performance
- `/api/ipo-past-security-type` - Past IPOs filtered by security type

This data gap prevents us from displaying:
- Listing performance metrics on IPO detail pages
- Historical IPO trends and analysis
- Company listing history for investors
- Complete IPO database for research

### Business Value
- **Data Completeness:** 60% → 95% historical IPO coverage (target: 200+ past IPOs)
- **User Experience:** Enable listing performance display on detail pages
- **SEO Impact:** Historical data pages for long-tail search traffic
- **Analytics:** Enable trend analysis for investment research

### Success Metrics
- 200+ past IPOs backfilled with listing performance
- 90%+ matching accuracy for existing IPOs
- Data quality score > 95% (validated fields)
- Zero production database errors during backfill

### AC2: Data Extraction & Transformation
**Given** raw NSE past endpoint response
**When** data transformation logic executes
**Then** extracted data must be normalized to database schema:

1. **Field Mapping**
   ```typescript
   // NSE Response → Database Schema
   companyName → listing_performance.company_name (fallback if no IPO match)
   symbol → listing_performance.symbol
   listingDate → listing_performance.listing_date
   listingPrice → listing_performance.listing_price
   currentPrice → listing_performance.current_price
   // Calculated fields
   listingGain = ((listingPrice - issuePrice) / issuePrice) * 100
   listingGainPercent = listingGain
   ```

2. **Data Type Conversion**
   - Date strings → PostgreSQL `date` type
   - Price strings (₹1,234.50) → `decimal(10,2)`
   - Percentage calculations → `decimal(5,2)`
   - Symbol cleaning (whitespace, special chars)

3. **Null Handling**
   - Default to `NULL` for missing optional fields
   - Log warning for missing critical fields (company name, symbol)
   - Skip records with < 3 required fields

4. **Data Validation**
   - Listing date must be in past
   - Prices must be positive numbers
   - Listing gain calculation validates against issue price (if available)
   - Symbol format: alphanumeric + optional suffix (e.g., LTIM-EQ)

5. **Deduplication**
   - Identify duplicates by symbol + listing date
   - Keep most complete record (fewest NULL fields)
   - Log skipped duplicates

6. **Audit Trail**
   - Track source endpoint for each record (public-past-issues vs. ipo-past-security-type)
   - Record extraction timestamp
   - Log transformation errors with original data

### AC3: Data Matching & Validation
**Given** transformed past IPO data
**When** matching against existing IPOs in database
**Then** system must accurately link listing data to correct IPO records:

1. **Primary Matching Strategy** (Symbol-based)
   ```sql
   SELECT id FROM ipos WHERE symbol = $1 LIMIT 1
   ```
   - Match by NSE symbol (highest confidence)
   - If multiple matches, use closest listing date

2. **Fallback Matching Strategy** (Name-based)
   ```sql
   SELECT id FROM ipos
   WHERE similarity(company_name, $1) > 0.7
   ORDER BY similarity(company_name, $1) DESC
   LIMIT 1
   ```
   - Use PostgreSQL `pg_trgm` trigram similarity
   - Threshold: 70% similarity
   - Handle company name variations (Ltd, Limited, Pvt Ltd)

3. **Unmatched Records Handling**
   - Store in `listing_performance` with NULL `ipo_id`
   - Log company names with no match for manual review
   - Generate report of unmatched companies (CSV export)

4. **Match Confidence Scoring**
   - Symbol match: 100% confidence
   - Name match > 90% similarity: 90% confidence
   - Name match 70-90% similarity: 70% confidence
   - No match: 0% confidence (flag for review)

5. **Validation Rules**
   - If matched IPO has `listing_date`, compare with NSE data (< 7 days diff acceptable)
   - If matched IPO has `issue_price`, validate listing gain calculation
   - Flag mismatches for manual review

6. **Conflict Resolution**
   - If existing `listing_performance` record exists, compare data quality:
     - Prefer record with more non-NULL fields
     - Prefer record with newer `updated_at` timestamp
     - Keep NSE data as source of truth (overwrite if NSE more complete)

7. **Matching Accuracy Validation**
   - Manual verification of 10% sample (minimum 20 IPOs)
   - Matching error rate must be < 5%
   - Log any mismatched IPOs for correction
   - Generate validation report with accuracy metrics

### AC4: Listing Performance Persistence
**Given** matched and validated listing data
**When** database insertion executes
**Then** `listing_performance` table must be updated correctly:

1. **Upsert Logic**
   ```sql
   INSERT INTO listing_performance (ipo_id, symbol, listing_price, ...)
   ON CONFLICT (ipo_id) DO UPDATE SET
     symbol = EXCLUDED.symbol,
     listing_price = EXCLUDED.listing_price,
     ...
   WHERE listing_performance.updated_at < EXCLUDED.updated_at
   ```

2. **One-to-One Relationship**
   - Each IPO has at most one `listing_performance` record
   - Foreign key constraint enforced: `listing_performance.ipo_id → ipos.id`
   - Orphaned records (NULL `ipo_id`) stored for future manual matching

3. **Timestamp Management**
   - `created_at` set on first insert (auto)
   - `updated_at` updated on every upsert (auto)
   - Track `data_source` = 'NSE_PAST_API'

4. **Transaction Safety**
   - All upserts within database transaction
   - Rollback on any error
   - Commit only after successful batch completion

5. **Batch Processing**
   - Process in batches of 50 records
   - Log progress after each batch
   - Resume capability if script interrupted

6. **Data Integrity Checks**
   - Verify foreign key constraints
   - Check for orphaned records (NULL `ipo_id`)
   - Validate unique constraints (one record per IPO)

### AC6: Data Quality Validation
**Given** backfill completes successfully
**When** data quality validation runs
**Then** inserted data must meet quality standards:

1. **Field Validation**
   - No NULL values in required fields: `symbol`, `listing_date`, `listing_price`
   - Date ranges: `listing_date` between 2015-01-01 and TODAY
   - Price ranges: `listing_price` > 0, `current_price` > 0
   - Listing gain: -100% < `listing_gain_percent` < 1000%

2. **Referential Integrity**
   - All matched records have valid `ipo_id` foreign key
   - Unmatched records have NULL `ipo_id` (acceptable)
   - No dangling foreign keys

3. **Duplicate Prevention**
   - No duplicate `ipo_id` in `listing_performance` table
   - No duplicate symbol + listing_date combinations

4. **Data Consistency**
   - If IPO has `listing_date`, it matches `listing_performance.listing_date` (±7 days)
   - If IPO has `issue_price`, listing gain calculation is consistent
   - `data_source` field set to 'NSE_PAST_API' for all backfilled records

5. **Quality Score Calculation**
   ```typescript
   qualityScore = (
     (recordsWithAllRequiredFields / totalRecords) * 0.4 +
     (recordsWithCurrentPrice / totalRecords) * 0.3 +
     (matchedRecords / totalRecords) * 0.3
   ) * 100
   // Target: > 95%
   ```

- **Response Structure:**
  ```json
  [
    {
      "companyName": "Jio Financial Services Ltd",
  ```

### Backfill Script Implementation Pattern

**File:** `scraper/src/scripts/backfill-historical-ipos.ts`

**Core Logic Flow:**
```typescript
async function backfillHistoricalIPOs(options: BackfillOptions): Promise<BackfillReport> {
  const logger = getLogger('backfill-historical');
  const db = await getDb();
  const redis = getRedisClient();

  // Step 1: Initialize NSE session
  logger.info('Initializing NSE session...');
  await initNSESession(); // From Story 11.3

  // Step 2: Fetch past IPOs
  logger.info('Fetching past IPOs from NSE...');
  const pastIPOs = await fetchPastIPOs();
  logger.info({ count: pastIPOs.length }, 'Fetched past IPOs');

  // Step 3: Transform & validate
  const transformed = pastIPOs
    .map(transformPastIPO)
    .filter(validatePastIPO);

  // Step 4: Match against existing IPOs
  const matchResults = await Promise.all(
    transformed.map(async (pastIPO) => {
      const match = await matchIPO(pastIPO);
      return { pastIPO, match };
    })
  );

  // Step 5: Batch upsert
  const repository = new ListingPerformanceRepository(db, redis);
  const batches = chunk(matchResults, options.batchSize);

  let totalInserted = 0, totalUpdated = 0, totalFailed = 0;

  for (const [index, batch] of batches.entries()) {
    logger.info({ batchNumber: index + 1, batchSize: batch.length }, 'Processing batch');

    if (options.dryRun) {
      logger.info('Dry-run mode: Skipping database write');
      continue;
    }

    const batchData = batch.map(({ pastIPO, match }) => ({
      ...pastIPO,
      ipo_id: match.ipoId,
    }));

    const result = await repository.batchUpsert(batchData);
    totalInserted += result.inserted;
    totalUpdated += result.updated;
    totalFailed += result.failed;

    // Rate limiting
    await delay(2000);
  }

  // Step 6: Generate report
  const report: BackfillReport = {
    totalFetched: pastIPOs.length,
    totalProcessed: transformed.length,
    matched: matchResults.filter(r => r.match.ipoId).length,
    unmatched: matchResults.filter(r => !r.match.ipoId).length,
    inserted: totalInserted,
    updated: totalUpdated,
    failed: totalFailed,
    qualityScore: calculateQualityScore(matchResults),
    duration: Date.now() - startTime,
    unmatchedCompanies: matchResults
      .filter(r => !r.match.ipoId)
      .map(r => r.pastIPO.company_name),
  };

  logger.info(report, 'Backfill completed');
  return report;
}
```

**Checkpoint/Resume Logic:**
```typescript
// Store checkpoint after each batch
const CHECKPOINT_FILE = 'backfill-checkpoint.json';

async function saveCheckpoint(batchNumber: number) {
  await fs.writeFile(CHECKPOINT_FILE, JSON.stringify({ lastBatch: batchNumber }));
}

async function loadCheckpoint(): Promise<number> {
  try {
    const data = await fs.readFile(CHECKPOINT_FILE, 'utf-8');
    const { lastBatch } = JSON.parse(data);
    return lastBatch + 1; // Resume from next batch
  } catch {
    return 0; // Start from beginning
  }
}
```
