## Story

**As a** retail investor researching an IPO,
**I want** to see anchor investor allocation data with lock-in periods and individual investor details,
**so that** I can gauge institutional confidence in the IPO and make informed investment decisions.

---

## Acceptance Criteria

1. Database migration creates `anchor_investors` table with all required fields (id, ipo_id, bid_date, total_shares_offered, total_amount_raised, anchor_investors_count, lock_in_50_percent_date, lock_in_remaining_date, investor_list, created_at, updated_at)
2. AnchorInvestorsSection component created in appropriate location following project structure
3. Component displays aggregate anchor data (bid date, shares offered, anchor portion amount, total investors count)
4. Component displays lock-in period dates (50% at 30 days, remaining at 90 days from bid date)
5. Component displays investor list table with columns (Investor Name, Type, Shares Allocated, Amount in ₹ Crores, % of Issue) when data exists
6. Empty state handled gracefully displaying "Anchor data not available yet" message
7. Component integrated into IPO detail page below Promoter Holding section or in dedicated tab
8. Unit tests for AnchorInvestorsSection component achieve >80% code coverage
9. Integration test validates database table creation and foreign key relationships
10. Admin panel allows manual anchor data entry with validation for required fields

### Data Models

**Database Schema - anchor_investors table:**
[Source: User requirements in epic-11-sharded.md]

```sql
CREATE TABLE anchor_investors (
  id UUID PRIMARY KEY DEFAULT gen_random_uuid(),
  ipo_id UUID NOT NULL REFERENCES ipos(id) ON DELETE CASCADE,
  bid_date DATE NOT NULL,
  total_shares_offered BIGINT NOT NULL CHECK (total_shares_offered > 0),
  total_amount_raised NUMERIC(12, 2) NOT NULL CHECK (total_amount_raised >= 0),
  anchor_investors_count INTEGER NOT NULL CHECK (anchor_investors_count >= 0),
  lock_in_50_percent_date DATE NOT NULL,
  lock_in_remaining_date DATE NOT NULL,
  investor_list JSONB, -- [{name, type, shares, amount, percentOfIssue}, ...]
  created_at TIMESTAMPTZ NOT NULL DEFAULT NOW(),
  updated_at TIMESTAMPTZ NOT NULL DEFAULT NOW()
);

CREATE INDEX idx_anchor_investors_ipo_id ON anchor_investors(ipo_id);
CREATE INDEX idx_anchor_investors_bid_date ON anchor_investors(bid_date);
```

**TypeScript Types:**
```typescript
// Drizzle-inferred types
export type AnchorInvestor = InferSelectModel<typeof schema.anchorInvestors>;
export type NewAnchorInvestor = InferInsertModel<typeof schema.anchorInvestors>;

// JSONB investor_list structure
export interface IndividualInvestor {
  name: string;
  type: 'Mutual Fund' | 'FII' | 'Insurance' | 'Bank' | 'AIF' | 'Other';
  shares: number;
  amount: number; // in crores
  percentOfIssue: number;
}
```

**Validation Schema:**
[Source: Best practices from existing validation patterns]

```typescript
import { z } from 'zod';

export const individualInvestorSchema = z.object({
  name: z.string().min(1).max(200),
  type: z.enum(['Mutual Fund', 'FII', 'Insurance', 'Bank', 'AIF', 'Other']),
  shares: z.number().positive(),
  amount: z.number().nonnegative(),
  percentOfIssue: z.number().min(0).max(100),
});

export const anchorInvestorSchema = z.object({
  ipo_id: z.string().uuid(),
  bid_date: z.string().date() or z.date(),
  total_shares_offered: z.number().positive().int(),
  total_amount_raised: z.number().nonnegative(),
  anchor_investors_count: z.number().nonnegative().int(),
  lock_in_50_percent_date: z.string().date() or z.date(),
  lock_in_remaining_date: z.string().date() or z.date(),
  investor_list: z.array(individualInvestorSchema).nullable(),
});
```
