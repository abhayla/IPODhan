### The defect this closes

`scraper/src/index.ts` runs ~12 post-scrape steps, each in a non-fatal `try/catch`.
`triggerStatusUpdate()` silently returned early when `ADMIN_API_TOKEN` was unset. A cycle
could therefore exit **0** with IPO statuses stale and nothing alerting. Round-6/7's P2-8
(tiered scheduler never scheduled) is the same class at design time; this is the runtime twin.

### Item 1 — post-scrape step ledger

Every step writes exactly one row to a new `scraper_steps` table:
`(cycle_id, step, status ok|skipped|failed, reason, duration_ms, created_at)`.
A `skipped` or `failed` status **requires** a reason at the type level (discriminated union) —
not just a convention one test happened to assert on one step (see checker round-1 F1 fix). The
catches stay non-fatal, but are no longer silent.

*Why a new table, not `scraper_logs`:* `scraper_logs.source` names a scrape SOURCE
(NSE/BSE/API_FALLBACK) and its status enum is SUCCESS/FAILURE/PARTIAL — no `skipped` state.
A documented skip could not be represented without overloading `source` and dropping the reason.

Migration `0033_add_scraper_steps.sql` is hand-authored (same as `0032`) because the journal is
blocked by a pre-existing, unrelated `extraction_status` enum-rename prompt.

### Item 2 — the nightly audit FAILs on a silently-dead step

Two checks in the T-335 detection-floor layer, the **runtime twin** of `i_wire_or_retire`
(which only proves a step is *wired*, never that it *worked*):

- `k_step_ledger_silence` — FAIL when an expected step has **zero `ok` rows in 24h**.
  `skipped` does not count as `ok`: a step skipped every cycle is still doing nothing.
- `k_step_consecutive_failures` — FAIL at **≥3 consecutive failed cycles**. 2 is a blip.

The expected-step list is **derived** from the exported `STEP_NAMES` at audit time
(`parseStepNames`), never hand-typed — a hand-typed copy is the `i_wire_or_retire` class itself.
A test asserts every derived name is actually passed to `runStep()`.

Also adds a **manifest↔script wiring test**: a check listed in `detection-checks.json` but never
recorded by the audit is a *paper* check that makes the coverage floor look wider than it is.
It earned its keep immediately — it caught item 4's check before it was documented.

### Item 3 — the scraper refuses to START without `ADMIN_API_TOKEN`

- **Runtime:** `assertRequiredEnvForCycle()` runs in `main()` before the first `runStep()` and
  throws naming every missing key; `main()`'s catch exits 1. Scoped to `--source=all` (single-source
  runs execute no post-scrape step). Blank counts as missing (T-230: presence ≠ validity).
- **Deploy:** two `assert-env-keys.sh` cases (missing + blank) using `run_case_grep`, so a message
  that stops *naming* the key fails too.
- **Drift guard:** `REQUIRED_ENV_FOR_ALL_CYCLE` is exported and a test binds it to the shell
  script's `SCRAPER_REQUIRED_KEYS`. Two hand-maintained lists in two languages is the drift class
  this task exists to kill.

`WEB_INTERNAL_URL` is deliberately **not** a startup requirement: its fallback
(`localhost:3001`) is correct on the prod box, so requiring it would break local `--source=all`
runs for zero safety gain. It stays deploy-time required only.

### Item 4 — daily NSE status cross-check

`l_nse_status_crosscheck` compares our OPEN/UPCOMING set against NSE's own current-issue and
all-upcoming feeds, using the same cookie handshake as `nse-api-client.ts`. FAILs, naming the
company, when we publish OPEN that NSE does not list, when NSE lists open what we call UPCOMING,
or when an NSE live issue has no row of ours at all.

Scope is narrow on purpose — MAINBOARD rows naming NSE among their listing exchanges. NSE Emerge
(SME) and BSE-only issues never appear on these endpoints; FAILing them would be noise, and a
muted channel is a dead mechanism.

**UNVERIFIABLE, never OK, when NSE is down** — and also when both feeds return zero usable rows,
since an empty feed is indistinguishable from a broken one. UNVERIFIABLE pages and exits 3
(T-321 silent-pass class). Checker round 1 executed this against **live NSE** and confirmed the
handshake, both feeds, and the naming path all work today (see checker report item 4).
