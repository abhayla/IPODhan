## Executive Summary

The Mainboard IPO Calendar is showing **test/seed data** generated by `seed-database.ts` script instead of real production data. This creates confusion as fictional IPO data appears alongside (or instead of) real market data. User requirement: **Calendar must show ONLY real production data from scrapers and manual entry, with NO test/seed data.**

**Solution**: Permanently delete all records with `data_source = 'SEED_SCRIPT'` from the database and add safeguards to prevent future test data in production.

## Root Cause Analysis

### Root Cause 1: Test Data in Production Database

**Problem**: Seed script (`web/scripts/seed-database.ts`) generates test IPO data with `data_source = 'SEED_SCRIPT'`.

**Evidence**:
```typescript
// web/scripts/seed-database.ts (lines 350-450)
await db.insert(ipos).values({
  // ... IPO fields ...
  dataSource: 'SEED_SCRIPT',  // ← Test data marker
  companyName: generateCompanyName(),  // ← Fictional names
  openDate: getRelativeDate(-45),  // ← Relative to today
});
```

**Impact**:
- Test data mixes with production data
- Calendar shows fictional IPOs
- Users cannot distinguish real vs test data
- Data quality issues

---

### Root Cause 2: Seed Script Uses Relative Dates

**Problem**: Test data is generated based on "today" ± X days, creating a rolling 70-day window.

**Evidence**:
```typescript
// Line 177-181
function getRelativeDate(daysFromToday: number): Date {
  const date = new Date();
  date.setDate(date.getDate() + daysFromToday);
  return date;
}

// Line 400-420
openDate: getRelativeDate(-45),  // 45 days ago
closeDate: getRelativeDate(-20), // 20 days ago
```

**Impact**:
- October 2025 has sparse data (>45 days ago, outside window)
- November 2025 has dense data (within 45-day window)
- Uneven distribution across months

---

### Root Cause 3: No Production Safeguards

**Problem**: Seed script can run in production environment without warnings or blocks.

**Evidence**:
- No `if (process.env.NODE_ENV === 'production')` check
- No warning messages about test data
- No confirmation prompt

**Impact**:
- Risk of accidentally running seed script in production
- No protection against test data pollution

### Task 6: Update Seed Script with Safeguards (10 minutes)

**Purpose**: Prevent future test data in production.

**File**: `web/scripts/seed-database.ts`

**Step 6.1**: Add production environment check (at top of main function)

**Location**: Before any database operations (~line 200)

```typescript
async function seedDatabase(options: SeedOptions = {}) {
  // ===== PRODUCTION SAFEGUARD =====
  console.warn(`
╔═══════════════════════════════════════════════════════════════╗
║                    ⚠️  WARNING: TEST DATA ONLY  ⚠️             ║
╚═══════════════════════════════════════════════════════════════╝

This seed script generates FICTIONAL TEST DATA for development only.

❌ DO NOT run this in production environment!
❌ Production should ONLY use scrapers and manual entry!

Data sources this script creates:
  • data_source = 'SEED_SCRIPT'
  • Fictional company names
  • Relative dates (today ± X days)
  • Random financial data

Production data sources (REAL DATA):
  • data_source = 'NSE_SCRAPER'
  • data_source = 'BSE_SCRAPER'
  • data_source = 'MONEYCONTROL'
  • data_source = 'MANUAL_ENTRY'
`);

  // Block execution in production
  if (process.env.NODE_ENV === 'production') {
    console.error('❌ BLOCKED: Seed script cannot run in production environment!');
    console.error('   Use scrapers or manual entry for production data.');
    process.exit(1);
  }

  // Require explicit confirmation in staging/development
  if (!options.force) {
    console.warn('\n⚠️  This will create test data in your database.');
    console.warn('   Use --force flag to confirm: npm run seed:force\n');
    process.exit(0);
  }

  console.log('✓ Proceeding with test data generation...\n');

  // ... existing seed logic ...
}
```

**Step 6.2**: Update package.json scripts


**Testing**:
