# Story 10.1: Fix Redis Connection Failure

**Epic**: 10 - Defect Fixing
**Story ID**: 10.1
**Issue ID**: ISS-001
**Priority**: 🔴 P0 - CRITICAL
**Status**: Draft

## Story

**As a** DevOps/System Administrator,
**I want** Redis server properly installed, configured, and running,
**so that** rate limiting and caching work correctly across all API endpoints

---

## Acceptance Criteria

1. **AC-1**: Redis server is installed and running
   - Verify with `redis-cli ping` returning PONG
   - Redis service starts automatically on system boot

2. **AC-2**: Application successfully connects to Redis
   - No connection errors in application logs
   - Connection pool established on startup
   - Graceful fallback if Redis unavailable (with clear warnings)

3. **AC-3**: Rate limiting is functional
   - API requests properly rate-limited per IP
   - Rate limit headers present in responses
   - TEST-001-4 passes (verify rate limiting with Redis active)

4. **AC-4**: Caching is operational
   - Cache writes succeed without errors
   - Cache reads retrieve stored data
   - Cache TTL respected
   - TEST-001-5 passes (test cache write and read operations)

5. **AC-5**: Health monitoring in place
   - Application startup checks Redis availability
   - Clear error message if Redis unavailable
   - Monitoring endpoint shows Redis status

## Dev Notes

### Issue Context (from TEST_ISSUES.json)

**Root Cause**: Redis server not started or not installed

**Evidence**:
```
[Redis] Connection error: Error: connect ECONNREFUSED 127.0.0.1:6379
[Redis] Max retries reached, stopping reconnection attempts
{"level":"error","msg":"Rate limit check failed"}
[Cache] Error getting key ipo:list:*: Connection is closed
```

**Affected Components**:
- Rate limiting (all API endpoints)
- API response caching
- Performance optimization
- Home page IPO service caching

### Relevant Source Tree

**Redis Client**: `lib/cache/redis-client.ts`
- Current implementation expects Redis at 127.0.0.1:6379
- Uses ioredis library (@types/ioredis in package.json)
- Implements retry logic (currently failing after max retries)

**Rate Limiting**: `lib/middleware/rate-limit.ts` or similar
- Depends on Redis for storing request counters per IP
- Falls back with error when Redis unavailable

**Caching**:
- Used in: `lib/services/home-ipo-service.ts`
- Cache keys follow pattern: `home:mainboard:active`, `ipo:list:*`, etc.
- TTL configured per cache type

### Technical Details

**Redis Configuration**:
- Default port: 6379
- Default host: 127.0.0.1 (localhost)
- No authentication required for local dev
- Production should use authentication

**Environment Variables**:
Check `.env.local` for Redis configuration:
```
REDIS_URL=redis://localhost:6379
# or individual vars
REDIS_HOST=127.0.0.1
REDIS_PORT=6379
```

### Testing

**Test Location**: Create `tests/integration/redis-connection.test.ts`

**Test Standards**:
- Use Vitest for integration tests
- Test file pattern: `*.test.ts` in `tests/integration/`
- Must test: connection, rate limiting, caching
- Use test database/Redis if available

**Testing Frameworks**:
- Vitest (already configured)
- `@vitest/coverage-v8` for coverage
- Run with: `npm run test:integration`

**Specific Test Requirements**:
1. Test Redis connection establishes successfully
2. Test rate limit enforcement with Redis
3. Test cache write/read cycle
4. Test graceful degradation if Redis unavailable
5. Test health check endpoint

### Prevention Measure

Add this to application startup (e.g., `lib/db.ts` or new `lib/startup.ts`):
```typescript
async function checkRedisHealth() {
  try {
    await redis.ping();
    console.log('✅ Redis connection established');
  } catch (error) {
    console.warn('⚠️  Redis not available - rate limiting and caching disabled');
    console.warn('   Install Redis: https://redis.io/download');
  }
}
```
