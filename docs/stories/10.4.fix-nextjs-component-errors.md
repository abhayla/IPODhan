### Technical Details

**1. useRouter Import Fix**:

❌ **INCORRECT** (CommonJS):
```typescript
const { useRouter } = require('next/navigation');
```

❌ **INCORRECT** (Destructuring):
```typescript
import { useRouter as useNextRouter } from 'next/navigation';
const { useRouter } = useNextRouter; // Still wrong
```

✅ **CORRECT** (ES6):
```typescript
import { useRouter } from 'next/navigation';

export function Component() {
  const router = useRouter();
  return <div>...</div>;
}
```

**Important Notes**:
- Must use ES6 `import` syntax
- No destructuring in require
- Only works in Client Components ('use client')
- Next.js 13+ uses 'next/navigation', not 'next/router'

**2. Event Handler Props Fix**:

❌ **INCORRECT** (Passing handlers to Client Components):
```typescript
// Server Component
export default function Page() {
  const handleYearChange = (year: number) => {
    // ...
  };

  return <YearFilter onYearChange={handleYearChange} />; // ❌ ERROR
}
```

✅ **SOLUTION A** (Use URL searchParams):
```typescript
// YearFilter.tsx
'use client';
import { useRouter, useSearchParams } from 'next/navigation';

export function YearFilter() {
  const router = useRouter();
  const searchParams = useSearchParams();

  const handleYearChange = (year: number) => {
    const params = new URLSearchParams(searchParams.toString());
    params.set('year', year.toString());
    router.push(`?${params.toString()}`);
  };

  return <select onChange={(e) => handleYearChange(Number(e.target.value))}>...</select>;
}
```

✅ **SOLUTION B** (Use React Context):
```typescript
// contexts/FilterContext.tsx
'use client';
import { createContext, useContext, useState } from 'react';

const FilterContext = createContext(null);

export function FilterProvider({ children }) {
  const [year, setYear] = useState(2025);
  return (
    <FilterContext.Provider value={{ year, setYear }}>
      {children}
    </FilterContext.Provider>
  );
}

// YearFilter.tsx
export function YearFilter() {
  const { year, setYear } = useContext(FilterContext);
  return <select value={year} onChange={(e) => setYear(Number(e.target.value))}>...</select>;
}
```

**3. Cache Directive Fix**:

❌ **INCORRECT** (Conflicting directives):
```typescript
// app/api/ipos/route.ts
export async function GET(request: Request) {
  return NextResponse.json(data, {
    headers: {
      'Cache-Control': 'no-store',    // ❌ Conflicts
    },
  });
}

export const revalidate = 300;         // ❌ Conflicts with no-store
```

✅ **OPTION 1** (No caching - always fresh):
```typescript
export async function GET(request: Request) {
  return NextResponse.json(data, {
    headers: {
      'Cache-Control': 'no-store, no-cache, must-revalidate',
    },
  });
}
// No revalidate export
```

✅ **OPTION 2** (Cache with revalidation):
```typescript
export const revalidate = 300; // Revalidate every 5 minutes

export async function GET(request: Request) {
  return NextResponse.json(data);
  // No cache headers needed
}
```

✅ **OPTION 3** (On-demand revalidation):
```typescript
export const dynamic = 'force-dynamic'; // Opt out of static generation

export async function GET(request: Request) {
  return NextResponse.json(data);
}
```

**Cache Strategy Decision Matrix**:
| Route | Data Freshness Need | Recommended Strategy |
|-------|---------------------|---------------------|
| `/api/ipos` (list) | Medium (5-15 min) | `revalidate: 600` |
| `/api/ipos/[slug]` (detail) | Medium (5 min) | `revalidate: 300` |
| `/api/ipos/listings` | High (real-time) | `cache: 'no-store'` |
| `/api/calendar` | Low (daily) | `revalidate: 86400` |
| `/api/gmp` | High (frequent updates) | `cache: 'no-store'` |

# Next.js Component Patterns

## useRouter in Next.js 15

✅ Correct:
import { useRouter } from 'next/navigation';

❌ Incorrect:
const { useRouter } = require('next/navigation');

## Event Handlers in Client Components

Use URL searchParams or Context for state management.

## API Caching

Choose ONE strategy:
- cache: 'no-store' - No caching
- revalidate: 300 - Time-based revalidation
