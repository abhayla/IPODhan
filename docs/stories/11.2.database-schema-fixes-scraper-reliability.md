### Database Schema Details

**Current Schema** (BROKEN):
```typescript
// File: packages/shared/src/db/schema.ts (line 106)
issueSize: numeric('issue_size', { precision: 10, scale: 2 }) // in INR crores
```

**Current Limit:**
- `NUMERIC(10, 2)` = max 99,999,999.99 (₹999.99 crores)
- **31 IPOs exceed this limit** (largest: ₹25,175 crores)

**Fixed Schema** (REQUIRED):
```typescript
// File: packages/shared/src/db/schema.ts (line 106)
issueSize: numeric('issue_size', { precision: 15, scale: 2 }) // in INR crores (max ₹999,999 crores)
```

**New Limit:**
- `NUMERIC(15, 2)` = max 9,999,999,999,999.99 (₹999,999 crores = ₹9,999.99 billion)
- Supports all current and future large IPOs

**Migration SQL:**
```sql
-- File: web/drizzle/migrations/XXXX_increase_issue_size_limit.sql
ALTER TABLE ipos ALTER COLUMN issue_size TYPE NUMERIC(15, 2);

-- Optional: Add CHECK constraint for data integrity
ALTER TABLE ipos ADD CONSTRAINT ipos_issue_size_positive CHECK (issue_size >= 0);
```

**Rollback SQL:**
```sql
-- File: web/drizzle/migrations/ROLLBACK_increase_issue_size_limit.sql
ALTER TABLE ipos ALTER COLUMN issue_size TYPE NUMERIC(10, 2);
ALTER TABLE ipos DROP CONSTRAINT IF EXISTS ipos_issue_size_positive;
```

### Error Logging Architecture

**Current Issue:**
```
Error: Failed to create IPO
Detail: undefined
```

**Target Logging:**
```
Error: Failed to create IPO - constraint violation
Code: 22003
Constraint: ipos_issue_size_check
Column: issue_size
Detail: numeric field overflow. A field with precision 10, scale 2 must round to absolute value less than 10^10.
Hint: Consider increasing the precision of the field.
IPO Data: { slug: "canara-hsbc-life-insurance-ipo", issueSize: "2517500000000" }
```

**PostgreSQL Error Codes:**
- `23505` - Unique violation (duplicate slug, ISIN, etc.)
- `23502` - Not null violation (missing required field)
- `22003` - Numeric field overflow (issue_size too large)
- `08000` - Connection exception (transient, should retry)
- `08003` - Connection does not exist (transient, should retry)
- `08006` - Connection failure (transient, should retry)

**Enhanced Error Logging Pattern:**
```typescript
// File: scraper/src/services/data-persister.ts
try {
  await db.insert(ipos).values(ipoData);
} catch (error: any) {
  logger.error({
    error: error.message,
    code: error.code,           // PostgreSQL error code
    constraint: error.constraint, // Constraint name (if violation)
    column: error.column,       // Column name (if violation)
    detail: error.detail,       // Detailed error message
    hint: error.hint,           // PostgreSQL hint for fixing
    ipoData: {
      slug: ipoData.slug,
      issueSize: ipoData.issue_size,
      companyName: ipoData.company_name
    }
  }, 'Failed to create IPO - constraint violation');

  // Skip retry for constraint violations (will always fail)
  if (['23505', '23502', '22003'].includes(error.code)) {
    throw error; // Don't retry
  }

  // Retry for transient errors
  if (['08000', '08003', '08006'].includes(error.code)) {
    await retryOperation();
  }
}
```

**Validation Before Insert:**
```typescript
// Validate issue_size fits in NUMERIC(15,2)
if (ipoData.issue_size && parseFloat(ipoData.issue_size) > 999999.99) {
  logger.error({
    slug: ipoData.slug,
    issueSize: ipoData.issue_size,
    maxAllowed: 999999.99
  }, 'Validation failed: issue_size exceeds NUMERIC(15,2) limit');
  return; // Skip insert
}

// Validate required fields
if (!ipoData.company_name) {
  logger.error({ slug: ipoData.slug }, 'Validation failed: company_name is required');
  return;
}
```

### Slug Collision Detection Architecture

**Current Issue:**
- No validation for duplicate slugs
- Potential edge case: "ABC Limited IPO" and "ABC Ltd IPO" → same slug `abc-limited-ipo`

**Solution:**
```typescript
// File: scraper/src/services/slug-generator.ts (or data-persister.ts)
async function generateUniqueSlug(companyName: string): Promise<string> {
  let slug = slugify(companyName); // abc-limited-ipo
  let counter = 1;

  // Check if slug exists
  while (await slugExists(slug)) {
    counter++;
    slug = `${slugify(companyName)}-${counter}`; // abc-limited-ipo-2
    logger.warn({ originalSlug: slugify(companyName), newSlug: slug }, 'Slug collision detected');
  }

  return slug;
}

async function slugExists(slug: string): Promise<boolean> {
  const result = await db.select({ id: ipos.id }).from(ipos).where(eq(ipos.slug, slug)).limit(1);
  return result.length > 0;
}
```

**Database UNIQUE Constraint:**
```sql

-- This prevents duplicate slugs at database level

```

## Risks & Mitigation

### Risk 1: Database Migration Fails on Production
**Likelihood**: Low
**Impact**: Critical
**Mitigation**:
- Test migration on staging environment first
- Create database backup before migration
- Document rollback procedure
- Test rollback on staging environment
- Schedule migration during low-traffic window

### Risk 2: Scraper Frequency Increase Causes Rate Limiting
**Likelihood**: Medium
**Impact**: Medium
**Mitigation**:
- Implement exponential backoff on rate limit errors
- Monitor scraper logs for rate limit warnings
- Reduce frequency if rate limiting detected (every hour instead of 30 min)
- Add User-Agent header to scraper requests
- Respect robots.txt

### Risk 3: HTML Structure Changes Break Field Extraction
**Likelihood**: Low
**Impact**: Medium
**Mitigation**:
- Implement monitoring to detect extraction failures
- Use flexible CSS selectors (multiple fallbacks)
- Log extraction failures for manual review
- Document selectors for easy updates

### Risk 4: Slug Collision Rate Higher Than Expected
**Likelihood**: Low
**Impact**: Low
**Mitigation**:
- Monitor collision logs (should be <1% of IPOs)
- If rate >5%, investigate root cause (slug generation logic)
- Consider more unique slug format (e.g., include year or BSE code)
