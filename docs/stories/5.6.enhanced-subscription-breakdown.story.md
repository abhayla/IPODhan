# Story 5.6: Enhanced Subscription Breakdown

## Status
Draft

## Story

**As a** serious IPO investor,
**I want** to see granular subscription breakdown with all 7 categories (QIB, NII with bNII/sNII split, Retail with HNI/Others split, Anchor Investors, Employee),
**so that** I can analyze the quality of demand and understand which investor categories are showing strong interest in the IPO.

## Acceptance Criteria

1. **Subscription Tab Display Enhancement**
   - Current display shows 3 categories (QIB, NII, Retail)
   - Enhanced display shows 7 categories:
     - QIB (Qualified Institutional Buyers)
     - NII split into: bNII (Big NII ≥₹10L), sNII (Small NII <₹10L)
     - Retail split into: Retail HNI, Retail Others
     - Anchor Investors (separate category)
     - Employee (if applicable)
   - "Detailed View" toggle to switch between Simple (3) and Detailed (7) views
   - Default view: Simple (backward compatible)

2. **Detailed View Table**
   - Table with columns: Category, Applications, Shares Bid, Shares Offered, Subscription (x times)
   - All 7 categories listed with individual data
   - Visual progress bars showing subscription multiples
   - Color coding: >1x (green), 0.5-1x (yellow), <0.5x (red)
   - Total row at bottom showing aggregate subscription

3. **Toggle UI Component**
   - Toggle button or tabs: "Simple View" vs "Detailed View"
   - User preference saved in local storage
   - Smooth transition between views
   - Mobile responsive (stacked cards for detailed view on mobile)

4. **Anchor Investor Highlight**
   - Anchor investor subscription shown prominently
   - Tooltip explaining: "Anchor investors subscribe before IPO opens, signaling strong institutional interest"
   - Show anchor allocation amount and % of total issue
   - Highlighted if anchor subscription is strong (>30% of issue size)

5. **Data Validation**
   - Ensure bNII + sNII = NII total
   - Ensure Retail HNI + Retail Others = Retail total
   - Handle null/zero values gracefully (show "-" or "N/A")
   - Show "Data unavailable" if granular breakdown doesn't exist

6. **Educational Tooltips**
   - Each category has tooltip explaining what it means
   - bNII: "Big NII - Individual bids ≥₹10 lakh"
   - sNII: "Small NII - Individual bids <₹10 lakh"
   - Retail HNI: "High Net Worth Individuals in retail category"
   - Anchor: "Pre-IPO allocation to institutional investors"

### Repository Pattern Context
[Source: CLAUDE.md#repository-pattern-with-caching]

**Repository should already include all fields**, just need to ensure they're returned:

```typescript
// web/lib/repositories/subscription-repository.ts
async findLatestByIPOId(ipoId: string): Promise<Subscription | null> {
  const cacheKey = `subscription:latest:${ipoId}`;
  return this.getFromCache(cacheKey, async () => {
    const result = await this.db
      .select()
      .from(schema.subscriptions)
      .where(eq(schema.subscriptions.ipoId, ipoId))
      .orderBy(desc(schema.subscriptions.timestamp))
      .limit(1);

    // Returns all fields including granular breakdown
    return result[0] || null;
  }, 180); // 3-min TTL
}
```

### Validation Logic

```typescript
// Utility to validate subscription data integrity
function validateSubscriptionTotals(sub: Subscription): {
  valid: boolean;
  warnings: string[];
} {
  const warnings: string[] = [];

  // Check NII breakdown
  const niiSum = sub.bNIISubscription + sub.sNIISubscription;
  if (Math.abs(niiSum - sub.niiSubscription) > 0.01) {
    warnings.push(`NII total mismatch: ${niiSum} vs ${sub.niiSubscription}`);
  }

  // Check Retail breakdown
  const retailSum = sub.retailHNISubscription + sub.retailOthersSubscription;
  if (Math.abs(retailSum - sub.retailSubscription) > 0.01) {
    warnings.push(`Retail total mismatch: ${retailSum} vs ${sub.retailSubscription}`);
  }

  return {
    valid: warnings.length === 0,
    warnings
  };
}
```
