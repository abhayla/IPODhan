## Story
**As a** user researching IPOs,
**I want** a comprehensive detail page that loads quickly and displays all IPO information in an organized manner,
**so that** I can make informed investment decisions based on complete data.

## Acceptance Criteria
1. Detail page at `/ipos/[slug]` route
2. Server-side rendering for Tier 1 data (above fold)
3. Client-side tabs for Tier 2 data (Overview, Financials, Subscription, GMP, Documents)
4. Progressive loading: Tier 1 → Tier 2
5. URL updates on tab switch (e.g., `/ipos/tech-corp?tab=financials`)
6. Breadcrumbs navigation (Home > IPOs > Company Name)
7. 404 page for invalid slugs
8. SEO metadata (title, description, Open Graph)
9. Structured data (JSON-LD for IPO entity)
10. Loading states for all async data
11. Error boundaries for component failures
12. Mobile-responsive layout
13. Page load <2 seconds (Lighthouse >90)
14. Smooth tab transitions (<500ms)

## Dev Notes

### Previous Story Insights

**From Story 4.1 (GET /api/ipos/[slug] Route):**
Story 4.1 implemented the backend API endpoint GET /api/ipos/[slug] that returns complete IPO details including financials, subscriptions (latest), GMP history (7-day), documents, peers, and registrar data. The endpoint uses Redis caching with 15-minute TTL and achieves <500ms response time. Story 4.3 will consume this API endpoint using the API client service to fetch data server-side.

Key implementation notes from Story 4.1:
- API route: `web/app/api/ipos/[slug]/route.ts`
- Response type: `IPODetailResponse` (includes IPO object + peers + metadata)
- Cache key: `ipo:detail:{slug}` with 900s TTL
- Error handling: Returns 404 for invalid slug, 500 for server errors
- All relations included: financials, documents, subscriptions (latest), gmp_records (7-day), peers

**From Story 4.2 (Detail Page Components):**
Story 4.2 created 12 reusable React components for the IPO detail page, including IPOHeader, KeyMetricsCards, InfoSection, SubscriptionBreakdown, GMPChart, FinancialTable, PeerComparisonTable, DocumentList, CompanyOverview, RatingDisplay, ShareButtons, and AllotmentCheckerCard. All components are TypeScript-typed, mobile-responsive, and include loading skeleton variants.

Key implementation notes from Story 4.2:
- All components located in: `web/src/components/ipo/`
- Components use shadcn/ui base components (Card, Table, Button, Input, Accordion, Skeleton)
- Loading skeletons exported from `web/src/components/ipo/skeletons.tsx`
- All components are Client Components ('use client' directive)
- Recharts library installed for GMPChart
- Components follow mobile-first responsive design

**From Story 3.1 (API Client Service):**
Story 3.1 implemented the frontend API client service at `web/lib/api-client.ts` with methods for fetching IPO data. Story 4.3 will use `getIPOBySlug(slug)` to fetch complete IPO details server-side in the page component.

### Progressive Loading Strategy

[Source: architecture/core-workflows.md#workflow-1]
Workflow: User Views IPO Detail Page
1. User navigates to `/ipos/[slug]`
2. Next.js SSR: Fetch IPO data from API (with Redis cache)
3. Render Tier 1 data server-side (IPOHeader, KeyMetricsCards, InfoSection)
4. Send HTML to user (<2 seconds)
5. Client hydration: Tabs component becomes interactive
6. User clicks tab: Load tab content (Tier 2 data) client-side

**Tier 1 (Server-Side Rendered):**
- Above fold content
- Renders immediately with initial page load
- No client-side JavaScript required
- Components: IPOHeader, KeyMetricsCards, InfoSection

**Tier 2 (Client-Side Tabs):**
- Below fold content
- Loads progressively when user clicks tabs
- Uses React.lazy() and Suspense for code-splitting
- Tabs: Overview, Financials, Subscription, GMP, Documents

### URL State Management

[Source: epic-4-sharded.md#acceptance-criteria]
Tab state synced with URL:
- Default: `/ipos/[slug]` (Overview tab)
- Financials: `/ipos/[slug]?tab=financials`
- Subscription: `/ipos/[slug]?tab=subscription`
- GMP: `/ipos/[slug]?tab=gmp`
- Documents: `/ipos/[slug]?tab=documents`

Use Next.js `useRouter` and `useSearchParams` hooks:
```typescript
const router = useRouter();
const searchParams = useSearchParams();
const activeTab = searchParams.get('tab') || 'overview';

const handleTabChange = (tab: string) => {
  router.push(`/ipos/${slug}?tab=${tab}`, { scroll: false });
};
```
