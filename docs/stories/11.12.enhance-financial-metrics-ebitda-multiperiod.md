## Story Overview

### Business Context

Currently, IPODhan's IPO Detail Page displays basic financial metrics (Revenue, Profit, Net Worth) but lacks comprehensive financial analysis features that competitors like Chittorgarh provide. This creates a significant gap in investor decision-making capability.

**Current Coverage:** 55% of financial metrics features implemented
**Target Coverage:** 100% with this story
**Competitive Gap:** Chittorgarh shows EBITDA, multi-year comparison, YoY growth prominently

**User Impact:** Investors need comprehensive financial data to make informed IPO investment decisions. Missing EBITDA and multi-period comparison makes it difficult to assess:
- Operational profitability trends
- Revenue/profit growth trajectory
- Financial health year-over-year

### User Story

**As an** investor researching an IPO
**I want** to see comprehensive financial metrics including EBITDA and multi-year comparison with growth percentages
**So that** I can make informed investment decisions based on historical financial performance trends

### Value Proposition

- **For Investors:** Comprehensive financial analysis with industry-standard metrics (EBITDA)
- **For IPODhan:** Competitive parity with Chittorgarh + enhanced credibility as professional IPO research platform
- **For Business:** Increased user engagement and trust through professional-grade financial analysis

**YoY Growth Calculation Formula:**
```typescript
const calculateYoYGrowth = (current: number, previous: number): number => {
  if (!previous || previous === 0) return 0;
  return ((current - previous) / previous) * 100;
};

// Update inferred types
import { InferSelectModel, InferInsertModel } from 'drizzle-orm';
import * as schema from '@ipodhan/shared/db/schema';

export type FinancialData = InferSelectModel<typeof schema.financialData>;
export type NewFinancialData = InferInsertModel<typeof schema.financialData>;

// Helper type for multi-period financial metrics
export interface MultiPeriodFinancials {
  revenue: {
    fy2022: number | null;
    fy2023: number | null;
    fy2024: number | null;
    yoyGrowth: number | null; // FY2024 vs FY2023
  };
  profit: {
    fy2022: number | null;
    fy2023: number | null;
    fy2024: number | null;
    yoyGrowth: number | null;
  };
  ebitda: {
    fy2022: number | null;
    fy2023: number | null;
    fy2024: number | null;
    yoyGrowth: number | null;
  };
  totalIncome: {
    fy2022: number | null;
    fy2023: number | null;
    fy2024: number | null;
    yoyGrowth: number | null;
  };
  netWorth: number | null;
  totalAssets: number | null;
  reservesAndSurplus: number | null;
  ratios: {
    currentRatio: number | null;
    quickRatio: number | null;
    inventoryTurnover: number | null;
  };
  totalBorrowings: number | null;
}

// Utility function to transform database model to multi-period format
export function toMultiPeriodFinancials(data: FinancialData): MultiPeriodFinancials {
  const calculateYoY = (current: number | null, previous: number | null): number | null => {
    if (!current || !previous || previous === 0) return null;
    return ((current - previous) / previous) * 100;
  };

  return {
    revenue: {
      fy2022: data.revenueFy2022,
      fy2023: data.revenueFy2023,
      fy2024: data.revenueFy2024,
      yoyGrowth: calculateYoY(data.revenueFy2024, data.revenueFy2023),
    },
    profit: {
      fy2022: data.profitFy2022,
      fy2023: data.profitFy2023,
      fy2024: data.profitFy2024,
      yoyGrowth: calculateYoY(data.profitFy2024, data.profitFy2023),
    },
    ebitda: {
      fy2022: data.ebitdaFy2022,
      fy2023: data.ebitdaFy2023,
      fy2024: data.ebitdaFy2024,
      yoyGrowth: calculateYoY(data.ebitdaFy2024, data.ebitdaFy2023),
    },
    totalIncome: {
      fy2022: data.totalIncomeFy2022,
      fy2023: data.totalIncomeFy2023,
      fy2024: data.totalIncomeFy2024,
      yoyGrowth: calculateYoY(data.totalIncomeFy2024, data.totalIncomeFy2023),
    },
    netWorth: data.netWorth,
    totalAssets: data.totalAssets,
    reservesAndSurplus: data.reservesAndSurplus,
    ratios: {
      currentRatio: data.currentRatio,
      quickRatio: data.quickRatio,
      inventoryTurnover: data.inventoryTurnover,
    },
    totalBorrowings: data.totalBorrowings,
  };
}
```

## Risks & Mitigation

### Risk 1: Database Migration Failure

**Probability:** Low
**Impact:** High

**Mitigation:**
- Test migration on local database first
- Create database backup before production migration
- Test rollback migration before applying
- Use constraint validation to prevent bad data

**Contingency:**
- If migration fails, rollback immediately
- Investigate issue, fix migration script
- Re-test and re-apply

---

### Risk 2: Performance Degradation

**Probability:** Low
**Impact:** Medium

**Mitigation:**
- Monitor query execution time (<50ms target)
- Use caching (24-hour TTL)
- Optimize database queries (select only needed columns)
- Test with realistic dataset size

**Contingency:**
- If performance degrades, add database index on `ipo_id` (likely already exists)
- Increase cache TTL if needed
- Consider pagination if dataset grows significantly

---

### Risk 3: Data Quality Issues

**Probability:** Medium
**Impact:** Medium

**Mitigation:**
- Add database constraints (CHECK constraints for positive ratios)
- Validate data before insertion
- Handle null values gracefully in UI
- Manual data entry with validation

**Contingency:**
- If bad data entered, use admin panel or SQL to correct
- Add more comprehensive validation if needed
