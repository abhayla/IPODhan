## Story
**As a** platform administrator deploying IPODhan,
**I want** the application deployed to the Windows VPS with PM2, configured with Cloudflare, SSL, and production environment settings,
**so that** the site is accessible at https://ipodhan.com with secure, scalable, and reliable infrastructure ready for public launch.

## Acceptance Criteria
1. Site accessible at https://ipodhan.com with valid SSL certificate (A+ rating on SSL Labs)
2. PM2 running both apps successfully: ipodhan-web (2 instances, cluster mode) and ipodhan-scraper (1 instance, fork mode)
3. Scraper executing on schedule and updating database
4. Database (PostgreSQL) and Cache (Redis) connected and accessible
5. Cloudflare caching active and verified in response headers
6. Production environment variables configured securely (not in Git)
7. Auto-restart on crash enabled for both PM2 apps
8. Log rotation enabled for PM2 logs
9. Production build optimized: All static assets minified and gzipped
10. Health check endpoint (`/api/health`) responding with status of database and Redis
11. Deployment documentation created in README for future deployments
12. Rollback procedure documented and tested

## Dev Notes

### Architecture Context
This story implements the production deployment strategy defined in the architecture documents. The deployment uses a Windows Server 2022 VPS with PM2 for process management, PostgreSQL for database, Redis for caching, and Cloudflare for CDN, SSL, and DDoS protection.

[Source: architecture/deployment-architecture.md]

### Deployment Architecture

**Platform:**
- Windows Server 2022 VPS (self-hosted)
- Node.js 20 LTS runtime
- PM2 5.3+ for process management
- Cloudflare CDN for static assets and SSL

**Applications:**
1. **ipodhan-web:** Next.js 14.2+ application serving frontend and API routes
   - 2 instances in cluster mode for load balancing
   - Max memory: 500MB per instance
   - Auto-restart on crash
   - Logs: `logs/web-error.log`, `logs/web-out.log`

2. **ipodhan-scraper:** Separate Node.js process for data scraping
   - 1 instance in fork mode
   - Max memory: 300MB
   - Cron restart: Daily at 3 AM
   - Logs: `logs/scraper-error.log`, `logs/scraper-out.log`

[Source: architecture/deployment-architecture.md#deployment-strategy, architecture/deployment-architecture.md#pm2-configuration]

### Database Configuration

**PostgreSQL 16+:**
- Database name: `ipodhan`
- Connection pooling: Max 20 connections
- Idle timeout: 30 seconds
- Connection timeout: 2 seconds
- Schema managed by Drizzle ORM migrations

**Redis 7.2+:**
- In-memory cache for API responses
- Memory limit: 256MB
- Eviction policy: allkeys-lru (Least Recently Used)
- Cache TTLs:
  - IPO List: 5 minutes
  - IPO Detail: 15 minutes
  - Subscription data: 10 minutes

[Source: architecture/backend-architecture.md#database-architecture, architecture/security-and-performance.md#caching-strategy]

### Cloudflare Configuration

**DNS:**
- A record for root domain (@) pointing to VPS IP (Proxied)
- Optional: www subdomain CNAME or A record

**SSL/TLS:**
- Encryption mode: Full (strict)
- HSTS enabled with preload
- Always Use HTTPS enabled
- Automatic HTTPS Rewrites enabled
- Target SSL Labs rating: A+

**Caching:**
- Static assets (`_next/static/*`): Cache Everything, 1 month TTL
- API routes (`/api/*`): Bypass or Standard with Cache-Control headers
- IPO pages (`/ipos/*`): Cache Everything, 5 minutes TTL
- Auto Minify: HTML, CSS, JavaScript enabled
- Brotli compression enabled

**Security:**
- Security Level: Medium
- DDoS protection: Enabled by default
- Optional: Bot fight mode, firewall rules, rate limiting

[Source: architecture/deployment-architecture.md#deployment-strategy, architecture/security-and-performance.md#security-requirements]

**Security Note:** NEVER commit `.env.production` to Git. Transfer securely via SCP or create manually on server with restricted permissions (chmod 600).

[Source: architecture/deployment-architecture.md#environments]

### Build Process

**Web Application:**
```bash
cd web
npm run build
```
- Creates optimized production build in `.next/` directory
- Includes static assets, server-side code, and API routes
- Requires `node_modules/` for runtime dependencies

**Scraper Service:**
```bash
cd scraper
npm run build
```
- Compiles TypeScript to JavaScript in `dist/` directory
- Output: `dist/index.js` (entry point)
- Requires `node_modules/` for runtime dependencies

[Source: architecture/deployment-architecture.md#deployment-strategy]

  "status": "healthy",

  "services": {
    "database": "healthy",

This endpoint is used by:

[Source: architecture/monitoring-and-observability.md#health-check-endpoint]

### PM2 Process Management

**Key Commands:**
- Start apps: `pm2 start ecosystem.config.js`
- Check status: `pm2 status`
- View logs: `pm2 logs [app-name] --lines [N]`
- Restart app: `pm2 restart [app-name]`
- Stop app: `pm2 stop [app-name]`
- Save configuration: `pm2 save`
- Monitor resources: `pm2 monit`

**Auto-Restart:**
- Enabled by default in PM2
- Restarts on crash or memory limit exceeded
- Cron restart for scraper: Daily at 3 AM

**Log Rotation:**
- Installed via: `pm2 install pm2-logrotate`
- Max log size: 10MB per file
- Retain: 7 days of logs
- Compression: Enabled (gzip)

[Source: architecture/deployment-architecture.md#pm2-configuration]

### Rollback Strategy

In case of deployment failure:
1. Stop current PM2 apps
2. Move current deployment to backup directory
