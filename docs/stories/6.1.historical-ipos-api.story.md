## Story
**As a** Rahul (active investor) or Priya (newcomer investor),
**I want** to access historical IPO data with filtering and sorting capabilities via API,
**so that** I can research past IPO performance, compare with current opportunities, and learn from historical trends to make better investment decisions.

## Acceptance Criteria
1. API endpoint at `GET /api/ipos/history`
2. Support filters: year, sector, performance
3. Support sorting: listing_date, listing_gain, subscription
4. Pagination with page and limit params
5. Returns IPO data with listing performance
6. Computed `listingGainPercent` field
7. Cache with Redis (24h TTL)
8. Error handling with proper status codes
9. Response matches defined TypeScript interface
10. Unit tests for API logic

## Dev Notes

### Previous Story Insights
Story 3.2 (API IPOs Route) and Story 4.1 (Get IPO Detail Route) established the pattern for creating API routes with filtering, caching, and error handling. Story 6.1 follows the same pattern with additional complexity for historical data filtering and computed fields (listingGainPercent, year).

The Repository Layer (Story 2.3) provides the foundation for data access with Drizzle ORM. This story extends the IPORepository with a new `findHistorical()` method specifically for querying listed IPOs with listing performance data.

### Data Models

export interface HistoricalIPO {

  listingGainPercent: number;    // Computed: ((listingClose - issuePrice) / issuePrice) * 100

### Database Requirements
**Database Schema** [Source: docs/epics/epic-6-sharded.md#database-requirements]:
- Use existing `ipos` table
- Filter on `status = 'LISTED'`
- Filter on `listing_date IS NOT NULL`
- Required fields for query:
  - `issue_price`, `listing_date`, `listing_open`, `listing_high`, `listing_close`
  - `subscription_overall`, `subscription_qib`, `subscription_nii`, `subscription_rii`
  - `sector`
- Computed fields:
  - `listing_gain_percent = ((listing_close - issue_price) / issue_price) * 100`
  - `year = YEAR(listing_date)`

**Indexes** [Source: docs/architecture/database-schema.md#important-indexes]:
- `idx_ipos_status` - Filter by status
- `idx_ipos_listing_date` - Sort by listing date
- Create new composite index for performance: `idx_ipos_listed_performance` on (status, listing_date, sector)

### API Specifications
**Endpoint Details** [Source: docs/epics/epic-6-sharded.md#api-endpoint]:
- Method: GET
- Path: `/api/ipos/history`
- Query Parameters: year, sector, performance, sort, sortOrder, page, limit
- Response Type: `HistoricalIPOResponse`
- Cache TTL: 24 hours (86400 seconds)
- Rate Limit: 100 requests/minute per IP

**Filtering Logic**:
- **Year Filter**: If year !== 'All', filter `YEAR(listing_date) = year`
- **Sector Filter**: If sector !== 'All', filter `sector = sector`
- **Performance Filter**:
  - If 'Positive': `listing_close > issue_price`
  - If 'Negative': `listing_close < issue_price`
  - If 'All': No filter

**Sorting Logic**:
- **listing_date**: ORDER BY `listing_date` {ASC|DESC}
- **listing_gain**: ORDER BY `((listing_close - issue_price) / issue_price * 100)` {ASC|DESC}
- **subscription**: ORDER BY `subscription_overall` {ASC|DESC}

**Pagination**:
- Default: page=1, limit=20
- SQL: `LIMIT {limit} OFFSET {(page - 1) * limit}`
- Calculate totalPages: `Math.ceil(total / limit)`

### Caching Strategy
**Cache-Aside Pattern** [Source: docs/architecture/api-specification.md#caching-strategy]:
- Redis cache with 24-hour TTL (86400 seconds)
- Cache key pattern: `ipos:history:{year}:{sector}:{performance}:{sort}:{sortOrder}:{page}:{limit}`
- Example: `ipos:history:2024:Technology:Positive:listing_gain:DESC:1:20`
- Cache invalidation: Wildcard pattern `ipos:history:*` when IPO status changes to 'LISTED' (Epic 7)
- For MVP: 24-hour TTL auto-expires cache (manual invalidation in Phase 2)

**Cache Implementation**:
```typescript
// Check cache
const cacheKey = `ipos:history:${year}:${sector}:${performance}:${sort}:${sortOrder}:${page}:${limit}`;
const cached = await redis.get(cacheKey);
if (cached) return JSON.parse(cached);

// Query database
const result = await IPORepository.findHistorical(params);

// Cache result (24 hours)
await redis.setex(cacheKey, 86400, JSON.stringify(result));
```

**Example Calculation**:
