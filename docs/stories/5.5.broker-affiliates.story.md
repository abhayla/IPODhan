# Story 5.5: Broker Affiliate Integration

## Status
Draft

**Created Date:** 2025-10-07

## Story
**As a** Priya (newcomer investor),
**I want** to see broker affiliate links on IPO pages and homepage,
**so that** I can easily open a demat account and start applying for IPOs while IPODhan earns commission.

## Acceptance Criteria
1. "Apply for this IPO" section on IPO detail page below key details
2. Two broker buttons displayed: Zerodha and AngelOne with logos
3. Buttons styled prominently but not overly aggressive
4. Affiliate links tagged with IPODhan referral codes
5. Homepage/dashboard banner: "New to IPO investing? Open a free demat account"
6. Homepage banner links to Zerodha and AngelOne with brief value props
7. Homepage banner is dismissible (hide for 7 days if user closes)
8. Affiliate links stored in `.env.local` as environment variables
9. Centralized config file: `lib/config/affiliate-links.ts`
10. Database table `affiliate_clicks` for tracking clicks
11. Google Analytics event tracking for all affiliate clicks
12. Footer disclaimer on every page with commission disclosure
13. Links open in new tab with `target="_blank" rel="noopener noreferrer"`
14. Mobile-responsive button layout
15. API endpoint `POST /api/affiliate/track` to log clicks

### API Specifications

**Affiliate Click Tracking Endpoint** [Source: docs/architecture/api-specification.md#broker-affiliates]:
- Method: POST
- Path: `/api/affiliate/track`
- Body: `{ ipoId?: string, brokerName: string, source: string }`
- Response: `{ success: boolean, timestamp: Date }`
- Rate Limit: 10 requests/minute per IP
- Validation: brokerName (zerodha/angelone), source (detail_page/homepage_banner)

**Get Active Broker Affiliates Endpoint** (Optional - can use config directly):
- Method: GET
- Path: `/api/affiliates`
- Response: `{ affiliates: BrokerAffiliate[] }`
- Cache TTL: Static data, no cache needed (use config file instead)

### Technical Constraints

**Input Validation** [Source: docs/architecture/coding-standards.md#critical-fullstack-rules]:
- Use Zod schema for API request body validation
- Validate brokerName: must be 'zerodha' or 'angelone'
- Validate source: must be 'detail_page' or 'homepage_banner'
- Optional ipoId: validate UUID format if provided

**Error Handling** [Source: docs/architecture/coding-standards.md#critical-fullstack-rules]:
- Use standard try/catch blocks with Next.js Response API
- Return user-friendly error messages with appropriate HTTP status codes
- Log validation errors for debugging
- Example pattern:
  ```typescript
  try {
    // logic
  } catch (error) {
    return Response.json({ error: 'Failed to track click' }, { status: 500 });
  }
  ```

**Rate Limiting**:
- Implement rate limiting middleware for `/api/affiliate/track`
- Limit: 10 clicks per IP per minute
- Prevent abuse and bot attacks
- Return 429 Too Many Requests if limit exceeded

**Anonymization** [Source: docs/epics/epic-5-sharded.md#tracking-analytics]:
- Hash user IP + user agent to generate anonymized session ID
- Do NOT store raw IP addresses or personally identifiable information
- Comply with privacy regulations (GDPR, data protection)

### Performance Considerations

**Click Tracking Performance**:
- Asynchronous API call (non-blocking)
- User navigates to broker site immediately (no delay)
- Track click in background (fire-and-forget pattern)
- Graceful degradation if tracking fails (still navigate user)

**Banner Dismissal Performance**:
- localStorage check on mount (fast, synchronous)
- No server-side rendering delay
- Instant dismissal (no API call needed)
- Efficient 7-day expiry check (compare timestamps)

**Database Performance**:
- Indexes on affiliate_clicks table for fast queries
- Batch analytics queries (not real-time)
- Archive old click data (>90 days) to maintain performance

### Security Considerations

**Rate Limiting** [Source: docs/architecture/api-specification.md#rate-limiting]:
- Prevent abuse by limiting clicks per IP per minute
- Protect database from spam/bot attacks
- Return 429 status code if rate limit exceeded

**Anonymization**:
- Hash user IP + user agent (no raw PII storage)
- Generate unique session ID for tracking
- Comply with privacy regulations

**Link Security**:
- Use `rel="noopener noreferrer"` on external links
- Prevent reverse tabnabbing attacks
- Validate affiliate URLs from environment variables
- Sanitize user inputs in API endpoint
