### Database Schema
**Source:** docs/architecture/database-schema.md, web/lib/db/schema.ts

**Core Tables:**
1. **ipos** - Main IPO entity with these key fields:
   - `id` (UUID), `companyName`, `slug` (unique), `category` (enum), `sector`
   - `issueSize` (numeric), `priceRangeMin`, `priceRangeMax`, `lotSize`
   - `status` (enum), `openDate`, `closeDate`, `allotmentDate`, `listingDate`
   - `companyDescription`, `faceValue`, `listingExchanges` (jsonb array)
   - `registrar`, `leadManagers` (jsonb array), `rating`, `ratingRationale`

2. **subscriptions** - Time-series subscription data:
   - `id`, `ipoId` (FK to ipos), `timestamp`
   - Subscription multiples: `qibSubscription`, `niiSubscription`, `retailSubscription`, `totalSubscription`
   - Granular: `anchorInvestorSubscription`, `retailHNISubscription`, `retailOthersSubscription`, `bNIISubscription`, `sNIISubscription`
   - Metrics: `totalApplications`, `totalSharesBid`, `sharesOffered`

3. **gmp_records** - Grey market premium tracking:
   - `id`, `ipoId` (FK), `timestamp`
   - `gmp` (₹), `expectedListingPrice`
   - Optional: `subjectRate`, `kostakRate`, `saudaDetails`

4. **financial_data** - Company financials (one-to-one with IPO):
   - `id`, `ipoId` (FK unique)
   - `revenue`, `profit`, `eps`, `peRatio`, `ronw`, `nav`, `pbRatio`
   - `totalAssets`, `totalLiabilities`, `netWorth`, `debtEquityRatio`
   - `statementType` (CONSOLIDATED | STANDALONE)

5. **documents** - IPO documents:
   - `id`, `ipoId` (FK), `documentType` (enum: DRHP, RHP, PROSPECTUS, ADDENDUM)
   - `title`, `url`, `uploadDate`

6. **listing_performance** - Post-listing metrics (one-to-one):
   - `id`, `ipoId` (FK unique), `listingPrice`, `listingGainPercent`
   - `currentPrice`, `currentGainPercent`, `marketCap`

7. **market_holidays** - Trading holidays:
   - `id`, `date`, `holidayName`, `holidayType` (TRADING | SETTLEMENT | BOTH), `exchange`

8. **registrars** - Registrar directory:
   - `id`, `name`, `website`, `email`, `phone`, `address`

9. **peer_companies** - Peer comparison data:
   - `id`, `ipoId` (FK), `peerName`, `peRatio`, `eps`, `dilutedEps`, `ronw`, `nav`, `pbRatio`

10. **broker_affiliates** - Affiliate broker links:
    - `id`, `brokerName`, `affiliateUrl`, `logoUrl`, `isActive`

**Enums:**
- `ipo_category`: MAINBOARD, SME, RIGHTS, NCD
- `ipo_status`: UPCOMING, OPEN, CLOSED, LISTED
- `document_type`: DRHP, RHP, PROSPECTUS, ADDENDUM
- `exchange`: NSE, BSE, BOTH
- `holiday_type`: TRADING, SETTLEMENT, BOTH
- `financial_statement_type`: CONSOLIDATED, STANDALONE

### Repository Usage Patterns
**Source:** docs/architecture/backend-architecture.md, Story 2.3 implementation

**Importing Repositories:**
```typescript
import { db } from '@/lib/db';
import { getRedisClient } from '@/lib/cache/redis-client';
import {
  IPORepository,
  SubscriptionRepository,
  GMPRepository,
  FinancialDataRepository,
  DocumentRepository,
  ListingPerformanceRepository
} from '@/lib/repositories';
```

**Creating Repository Instances:**
```typescript
const redis = getRedisClient();
const ipoRepo = new IPORepository(db, redis);
const subRepo = new SubscriptionRepository(db, redis);
const gmpRepo = new GMPRepository(db, redis);
const finRepo = new FinancialDataRepository(db, redis);
const docRepo = new DocumentRepository(db, redis);
const listRepo = new ListingPerformanceRepository(db, redis);
```

**Creating IPOs:**
```typescript
const ipo = await ipoRepo.create({
  companyName: 'Example Tech Ltd',
  slug: 'example-tech-ipo',
  category: 'MAINBOARD',
  sector: 'Technology',
  issueSize: 500,
  priceRangeMin: 100,
  priceRangeMax: 110,
  lotSize: 150,
  status: 'OPEN',
  openDate: new Date('2025-01-15'),
  closeDate: new Date('2025-01-17'),
  // ... other fields
});
```
