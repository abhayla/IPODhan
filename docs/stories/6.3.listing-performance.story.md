## Story
**As a** Rahul (active investor) or Priya (newcomer investor),
**I want** to see enhanced listing day performance with color-coded gains, performance badges, and historical context,
**so that** I can quickly evaluate how an IPO performed on listing day compared to its issue price and sector average, helping me learn from past IPO outcomes and make better investment decisions.

## Acceptance Criteria
1. Listing gain badge on historical IPO cards
2. Badge format: `+X.X%` or `-X.X%` with color coding
3. Listing Performance section on IPO detail page
4. Display: issue price, listing open/high/close, day return
5. Color-coded day return (green/red)
6. Historical context: Compare against sector average
7. Badge: "Above average" or "Below average"
8. Only show if `listing_date` is available
9. Structured data (JSON-LD) for historical IPO
10. Mobile-responsive component design

### Calculation Logic
**Source:** [docs/epics/epic-6-sharded.md#technical-implementation]

**Listing Gain Percent Calculation:**
```typescript
listingGainPercent = ((listingClose - issuePrice) / issuePrice) * 100
```

**Example Calculation:**
- Issue Price: ₹300
- Listing Close: ₹340
- Listing Gain: ((340 - 300) / 300) * 100 = 13.33%

**Percentage Gain for Each Metric:**
```typescript
openGain = ((listingOpen - issuePrice) / issuePrice) * 100
highGain = ((listingHigh - issuePrice) / issuePrice) * 100
closeGain = ((listingClose - issuePrice) / issuePrice) * 100
```

**Sector Average Calculation (Database Query):**
```sql
SELECT AVG((listing_close - issue_price) / issue_price * 100) AS sector_average
FROM ipos
WHERE status = 'LISTED' AND sector = 'Technology' AND listing_date IS NOT NULL
```

### Caching Strategy
**Source:** [docs/architecture/api-specification.md#caching-strategy]

**Sector Average Caching:**
- Redis cache key: `sector:average:listing-gain:{sector}`
- Example: `sector:average:listing-gain:Technology`
- Cache TTL: 7 days (604800 seconds) - sector averages change slowly
- Cache invalidation: When new IPO is listed, invalidate all sector average keys
- Cache-aside pattern: Check cache first, query DB if miss, then cache result

**Cache Implementation:**
```typescript
// Check cache
const cacheKey = `sector:average:listing-gain:${sector}`;
const cached = await redis.get(cacheKey);
if (cached) return parseFloat(cached);

// Query database
const average = await db.query(/* SQL query */);

// Cache result (7 days)
await redis.setex(cacheKey, 604800, average.toString());
```

### Coding Standards
**Source:** [docs/architecture/coding-standards.md]

**Critical Rules for Components:**
1. **Component Naming:** PascalCase (ListingPerformanceBadge.tsx)
2. **Props Interface:** Define explicit TypeScript interface
3. **Client Components:** Use 'use client' directive if interactivity needed (tooltips, hover effects)
4. **Type Safety:** Import types from shared package, never use 'any'
5. **Styling:** Tailwind CSS utility classes, no inline styles
6. **Accessibility:** Semantic HTML, ARIA labels for icons
7. **Error Handling:** Handle null/undefined values gracefully (conditional rendering)

**Component Structure Example:**
```typescript
'use client';

import { Badge } from '@/components/ui/badge';
import { TrendingUp, TrendingDown } from 'lucide-react';

interface ListingPerformanceBadgeProps {
  listingGainPercent: number;
  size?: 'small' | 'medium' | 'large';
  showIcon?: boolean;
}

export function ListingPerformanceBadge({
  listingGainPercent,
  size = 'medium',
  showIcon = true
}: ListingPerformanceBadgeProps) {
  if (!listingGainPercent) return null;

  const isPositive = listingGainPercent > 0;
  const Icon = isPositive ? TrendingUp : TrendingDown;

  return (
    <Badge className={/* Tailwind classes */}>
      {showIcon && <Icon className="w-4 h-4" />}
      {isPositive ? '+' : ''}{listingGainPercent.toFixed(2)}%
    </Badge>
  );
}
```
