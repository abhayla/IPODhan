## Story
**As a** IPODhan platform administrator,
**I want** additional data source scrapers for Moneycontrol and Chittorgarh websites that aggregate IPO information from multiple exchanges,
**so that** the platform achieves 99% data availability through redundant sources, provides GMP (Grey Market Premium) data, and ensures continuous IPO data flow even when primary NSE/BSE sources are unavailable.

## Acceptance Criteria
1. Moneycontrol scraper successfully extracts IPO data from `https://www.moneycontrol.com/ipo/`
2. Moneycontrol scraper extracts: company name, issue size, price range, dates, subscription data, and IPO rating
3. Chittorgarh scraper successfully extracts IPO data from `https://www.chittorgarh.com/ipo/ipo_list.asp`
4. Chittorgarh scraper extracts: company name, issue details, GMP (Grey Market Premium), and subscription data
5. Both scrapers validate data using Zod schemas before database insertion
6. Both scrapers implement data deduplication logic (merge with existing NSE/BSE data)
7. Both scrapers use Cheerio for HTML parsing (static content, faster than Puppeteer)
8. Scrapers fallback to Puppeteer if JavaScript rendering is detected
9. Both scrapers implement retry logic: 3 retries with exponential backoff (1s, 2s, 4s)
10. Both scrapers log operations with structured logging (success, failures, duration)
11. Both scrapers can be executed independently for testing
12. RSS feed parser implemented for Moneycontrol RSS feed as additional source

## Risks & Mitigation

### Risk 1: Website Structure Changes
- **Impact:** Scrapers break, data flow interrupted
- **Probability:** Medium (every 6-12 months)
- **Mitigation:**
  - Modular selector patterns for easy updates
  - Automated health checks every 5 minutes
  - Alert on 3+ consecutive failures
  - Quick selector update process (< 2 hours)
  - Fallback to other redundant sources

### Risk 2: GMP Data Accuracy
- **Impact:** Misleading investor information
- **Probability:** Low (Chittorgarh is established source)
- **Mitigation:**
  - Validate GMP within reasonable ranges (-50% to +200% of issue price)
  - Track GMP history for anomaly detection
  - Display "Last updated" timestamp prominently
  - Include disclaimer about GMP volatility
  - Code validation:
    ```typescript
    function validateGMP(gmp: number, issuePrice: number): boolean {
      const gmpPercentage = (gmp / issuePrice) * 100;

      // Reject unrealistic GMP values
      if (gmpPercentage > 200 || gmpPercentage < -50) {
        logger.warn(`Suspicious GMP: ${gmp} (${gmpPercentage}%)`);
        return false;
      }

      return true;
    }
    ```

### Risk 3: Rate Limiting Enforcement
- **Impact:** Scrapers blocked, data unavailable
- **Probability:** Low (both sites have minimal protection)
- **Mitigation:**
  - Respect robots.txt directives
  - Implement polite delays (2-3 seconds between requests)
  - Monitor response codes (429, 403)
  - Reduce frequency if rate limited
  - Use exponential backoff on errors

### Risk 4: Resource Exhaustion
- **Impact:** Server overload from concurrent scrapers
- **Probability:** Low with current scale
- **Mitigation:**
  - Staggered schedule implementation
  - Max 2 concurrent Puppeteer instances
  - Memory monitoring and alerts at 80% usage
  - Graceful degradation under load
  - Process isolation for each scraper

### Security Validation

**HTML Parsing Safety:**
- Use Cheerio (doesn't execute JavaScript) for initial parsing
- Sanitize all text content before database insertion
- Validate URLs before following redirects
- Escape special characters in company names
- Implement DOMPurify for HTML sanitization if storing HTML content

**Data Validation:**
- Zod schema validation for type safety
- Range checks for numerical values (GMP, issue size, prices)
- Date validation (open date < close date < listing date)
- Reject malformed or suspicious data
- Log validation failures for audit trail
