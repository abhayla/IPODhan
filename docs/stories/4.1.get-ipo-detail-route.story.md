## Story

**I want** a backend API endpoint that fetches complete IPO details by slug,
**so that** the detail page can display all necessary IPO information including financials, subscriptions, GMP history, documents, peers, and registrar data.

7. Includes documents (DRHP, RHP, Prospectus)
8. Includes registrar information
9. Proper error handling (404 for invalid slug)
10. Response time <500ms with caching
11. API documented with TypeScript types

### Data Models
[Source: architecture/data-models.md#ipo-core-entity]
The IPO entity includes:
- Basic info: id, companyName, slug, category, sector, issueSize, priceRange, lotSize, status
- Timeline: dates (openDate, closeDate, allotmentDate, listingDate)
- Additional: companyDescription, faceValue, listingExchanges, registrar, leadManagers
- Rating: rating (1-5 stars), ratingRationale
- Timestamps: createdAt, updatedAt

**Relationships:**
- Has many Subscription records (subscription history)
- Has many GMPRecord entries (GMP tracking)
- Has one FinancialData record (3-year trends)
- Has many Document records (DRHP, RHP, Prospectus)
- Has one ListingPerformance record (if listed)

[Source: architecture/data-models.md#subscription]
Subscription entity tracks category-wise subscription data:
- High-level categories: QIB, NII, Retail, Employee, Others, Total
- Timestamp for historical tracking
- Latest subscription = most recent timestamp

[Source: architecture/data-models.md#gmprecord]
GMPRecord tracks Grey Market Premium:
- ipoId, price, timestamp
- Subject rate, Kostak rate
- 7-day history = records from last 7 days

[Source: architecture/data-models.md#financialdata]
FinancialData contains:
- 3-year revenue/profit trends
- P/E ratio, EPS, Diluted EPS, RoNW, NAV, P/BV
- One-to-one relationship with IPO

### Database Schema
[Source: architecture/database-schema.md#key-tables]
Tables involved:
- `ipos` - Core IPO table
- `subscriptions` - Subscription snapshots
- `gmp_records` - GMP history
