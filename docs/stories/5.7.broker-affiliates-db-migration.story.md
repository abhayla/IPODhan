## Story

**As a** platform administrator,
**I want** to migrate the hardcoded broker affiliates array to the `broker_affiliates` database table,
**so that** I can dynamically manage broker partnerships, update affiliate links, and control display order without requiring code deployments.

## Acceptance Criteria

1. **Database Migration from Hardcoded Array**
   - Migrate existing 6 hardcoded brokers from `/affiliates` page to `broker_affiliates` table
   - Preserve all existing broker data: name, logo URL, affiliate URL, display text
   - Add display_order field to control sort order
   - Add active flag to enable/disable brokers

2. **Dynamic Broker Loading**
   - `/affiliates` page loads broker data from database (not hardcoded array)
   - Query filters by `active = true`
   - Sort by `display_order` ASC
   - Display same UI as current hardcoded version (backward compatible)

3. **Repository and Service Layer**
   - Create `BrokerAffiliateRepository` with caching
   - Implement `findAllActive()` method
   - Cache with 30-minute TTL
   - Cache key: `broker:affiliates:active`

4. **Seed Data Script Update**
   - Add broker affiliates to seed data script
   - Include realistic data (Zerodha, Upstox, AngelOne, Groww, 5paisa, ICICI Direct)
   - Set display_order (1-6)
   - All marked as active by default

5. **Admin-Friendly Data Structure**
   - Database fields support future admin panel
   - Fields: id, broker_name, broker_logo, affiliate_url, display_text, active, display_order
   - Enable easy updates via direct database edits (Phase 1)
   - Structure ready for admin UI (Phase 2)

6. **Backward Compatibility**
   - UI looks identical to current hardcoded version
   - No visual changes for end users
   - Same 6 brokers displayed in same order
   - All affiliate links work correctly

7. **Error Handling**
   - If database query fails, log error and show fallback message
   - Don't crash the page if broker data unavailable
   - Cache failures gracefully handled

### Repository Pattern Context
[Source: CLAUDE.md#repository-pattern-with-caching]

**Repository Implementation:**

```typescript
// web/lib/repositories/broker-affiliate-repository.ts
import { BaseRepository } from './base-repository';
import * as schema from '@ipodhan/shared/db/schema';

export class BrokerAffiliateRepository extends BaseRepository {
  async findAllActive(): Promise<BrokerAffiliate[]> {
    const cacheKey = 'broker:affiliates:active';
    return this.getFromCache(cacheKey, async () => {
      const results = await this.db
        .select()
        .from(schema.brokerAffiliates)
        .where(eq(schema.brokerAffiliates.active, true))
        .orderBy(asc(schema.brokerAffiliates.displayOrder));
      return results;
    }, 1800); // 30-min TTL
  }

  async invalidateCache(): Promise<void> {
    await this.deleteCache('broker:affiliates:active');
  }
}
```

**Cache Strategy:**
- Cache key: `broker:affiliates:active`
- TTL: 30 minutes (1800 seconds)
- Invalidation: Manual via admin action (Phase 2) or direct cache deletion

### Service Layer Context

```typescript
// web/lib/services/broker-affiliate-service.ts
import { BrokerAffiliateRepository } from '../repositories/broker-affiliate-repository';
import { getDb } from '../db';
import { getRedisClient } from '../cache/redis-client';

export async function getActiveBrokers(): Promise<BrokerAffiliate[]> {
  try {
    const db = await getDb();
    const redis = getRedisClient();
    const repository = new BrokerAffiliateRepository(db, redis);
    return await repository.findAllActive();
  } catch (error) {
    console.error('Failed to fetch broker affiliates:', error);
    return []; // Return empty array, don't throw
  }
}
```
