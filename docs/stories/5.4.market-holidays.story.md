# Story 5.4: Market Holidays Calendar

## Status
Draft

**Created Date:** 2025-10-07
**Story Points:** 4
**Priority:** Medium
**Dependencies:** None (standalone feature)
**Workflow:** automated-story-creation-workflow

## Story
**As a** Priya (newcomer investor),
**I want** to view NSE/BSE trading holidays in a calendar,
**so that** I can plan my IPO applications around market closures and understand IPO timelines.

## Acceptance Criteria
1. Market Holidays page at `/market-holidays`
2. Display holidays in chronological order (upcoming first)
3. Show for each holiday:
   - Date (DD MMM YYYY format, e.g., "26 Jan 2025")
   - Holiday name (e.g., "Republic Day", "Diwali")
   - Exchange(s) affected: NSE, BSE, or Both
   - Day of week (e.g., "Monday")
4. Highlight upcoming holidays (next 7 days) with visual badge
5. Past holidays shown in muted color
6. Filters:
   - Year: 2024, 2025, 2026 (default: current year)
   - Exchange: All, NSE Only, BSE Only
   - Upcoming / All toggle
7. Database table `market_holidays` with seed data from NSE/BSE calendars
8. Responsive: List view on mobile, table on desktop
9. Data seeded from NSE/BSE official calendars (manual entry for MVP)
10. Accessible from "Tools" menu in navigation
11. Loading states and error handling
12. Static page with ISR (revalidate every 30 days)

### Data Models

**MarketHoliday Interface** [Source: docs/architecture/data-models.md#marketholiday-mvp]:
```typescript
export enum Exchange {
  NSE = 'NSE',
  BSE = 'BSE',
  BOTH = 'BOTH'
}

export enum HolidayType {
  TRADING = 'TRADING',           // No trading on this day
  SETTLEMENT = 'SETTLEMENT',     // Settlement holiday only
  BOTH = 'BOTH'                  // Both trading and settlement
}

export interface MarketHoliday {
  id: string;
  date: Date;
  description: string;             // e.g., "Republic Day", "Diwali"
  exchange: Exchange;              // NSE, BSE, or BOTH
  type: HolidayType;
  year: number;                    // For filtering by year
  createdAt: Date;
  updatedAt: Date;
}
```

### API Specifications

**Endpoint Details** [Source: docs/architecture/api-specification.md#market-holidays]:
- Method: GET
- Path: `/api/market-holidays`
- Query Params: `year` (2024-2026), `exchange` (ALL/NSE/BSE), `upcoming` (boolean)
- Response: `{ holidays: MarketHoliday[], fetchedAt: Date }`
- Cache TTL: ISR revalidate every 30 days (2592000 seconds)
- Rate Limit: 100 requests/minute per IP

**Validation Rules**:
- Year: 2024-2026 (validate range)
- Exchange: ALL, NSE, BSE (validate enum)
- Upcoming: boolean (true/false)

**Error Responses**:
- 400 Bad Request: Invalid year or exchange value
- 500 Internal Server Error: Database or repository errors

**Rationale for 30-day revalidation**:
- Holiday data changes infrequently (annual updates)
- No real-time requirements
- Optimal for performance and CDN caching
- Manual revalidation possible via admin interface (Phase 2)
