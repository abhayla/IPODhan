## 🔑 Critical Information

### 1. Scoring Algorithm Breakdown

**Total Score: 100 points**

| Component | Weight | Sub-components |
|-----------|--------|----------------|
| Fundamentals | 40% | P/E (8), Revenue Growth (8), Profitability (8), Debt (5), ROE (5), Cash Flow (6) |
| Market Sentiment | 30% | GMP Trend (10), Watchlist (5), Social Buzz (5), Crowd Prediction (5), Search Trends (5) |
| Subscription | 20% | QIB (8), HNI (4), Retail (5), Momentum (3) |
| Sector Timing | 10% | Sector Performance (3), Peer Comparison (3), Market Condition (2), IPO Capacity (2) |

**Score Bands:**
- 70-100: "Strong Buy" 🟢
- 50-69: "Consider" 🟡
- 30-49: "Risky" 🟠
- 0-29: "Avoid" 🔴

### 2. Data Source Clarifications (v1.1 Updates)

#### Industry PE Benchmark (Fundamentals)
- **Primary:** NSE sector indices (monthly refresh)
- **Fallback:** Hardcoded averages (Tech: 35, BFSI: 20, Pharma: 30, Auto: 25, FMCG: 40)
- **If Unavailable:** Skip P/E component, recalculate weights proportionally
- **Implementation:** Store in `sector_benchmarks` table or fetch from NSE API

#### Social Buzz & Search Trends (Sentiment)
- **MVP Approach (Recommended):** Skip both components
  - Recalculate sentiment weights: GMP trend 12, watchlist 6, crowd 6, search 6
- **Future Enhancement:** Add Reddit/Twitter API + Google Trends API

#### Redis Caching
- **Connection example:** Full Python code provided (lines 723-742)
- **Key convention:** `score:{ipo_id}:latest`, `score:{ipo_id}:history:{days}`
- **TTL:** 3600 seconds (1 hour)
- **Operations:** `setex()` and `get()` examples provided (lines 753-765)

### 3. SME IPO Adjustments

Special handling for SME category IPOs:
- Higher risk penalty: **-5 points**
- Lower liquidity penalty: **-3 points**
- Growth potential bonus: **+8 points** (if revenue growth >40%)
- Promoter holding bonus: **+3 points** (if post-IPO holding >60%)
- Add `sme_warning` flag to response

**Ensure final score stays 0-100 bounded**

## 🚨 Critical "Gotchas" to Avoid

### 1. Missing Data Handling
**Problem:** Not all IPOs have complete financial data
**Solution:** Implement confidence assessment (AC11)
- HIGH: >90% fields populated
- MEDIUM: 60-90% fields
- LOW: <60% fields

### 2. Score Weight Recalculation
**Problem:** When skipping components (social buzz, search trends), weights don't add up
**Solution:** Recalculate proportionally (examples in Dev Notes lines 583-598)

### 3. SQL Injection Prevention
**Problem:** Raw SQL queries are vulnerable
**Solution:** Use parameterized queries 100% (repository pattern enforced)

### 4. Redis Connection Failures
**Problem:** Redis unavailable breaks API
**Solution:** Graceful degradation - fall back to database if Redis fails

### 5. SME Score Overflow
**Problem:** SME bonuses can exceed 100
**Solution:** Always cap final score: `min(max(score, 0), 100)`
