1. **OD-1 … OD-54 in the design are binding.** Where a card and a decision disagree, the decision wins and the card is corrected in the same slice (docs commit in the coordination worktree, D10-signed).

A slice is ≤ ~400 changed lines (git-collaboration.md); a slice that grows past it is split, never merged large. No second item starts before the current item is DONE (all slices merged AND staging proof recorded, or the item is BLOCKED on an owner decision and recorded as such).
3. **Item order** (dependency-ordered from §7.1; item 1 first by OD-10; 19 already done): **1, 20, 15, 13, 14, 12, 4, 2, 3, 5, 6, 7, 9, 10, 8, 16, 17, 18, 22, 21, 11.** Item 20 (the traceability CI check) is second so every later item is proven against its R-ids by CI, not by report. Item 7's cadence, wake script and crontab changes land as code plus a written deploy step for the owner (the run may not touch the VPS); its staging proof is OWED to the owner's deploy and the item is closed BLOCKED-OWNER, never proven by the run.
4. **Each slice is test-first:** the failing test is written and shown red (paste the red line) before the change; the same test green after; `.claude/rules/scraper-test-layout.md` decides tier and location; integration tests run against `ipodhan_test` after `npm run db:migrate` there (precondition (b)), never against staging or production. A slice adding a UNIQUE constraint or a NOT NULL column to a populated table MUST first prove, by a read-only query through the tunnel against `ipodhan_staging` AND `ipodhan`, pasted in the PR body, that zero rows violate it; if any do, a dedupe repair slice lands and is proven first; destructive DDL goes to `web/drizzle/migrations/_gated/` per the migration rule, never the journal. The red line MUST be produced by running the new test with the source change absent: a second worktree at `origin/main` with only the test file applied (never `git stash`, which a hook blocks); the paste shows the test file path and the assertion message; the `sonnet` verifier reproduces the red independently. The red-line worktree is created with `wt-new.ps1` (`-Name IPODhan-red-<item>-<slice> -Base origin/main -TtlHours 4`) and removed with `wt-rm.ps1 -Discard` immediately after the red run is pasted; it never outlives the slice.
5. **Merge authority (owner, 2026-09-09):** the run merges its own PRs with `gh pr merge <n> --squash` once (a) every CI check on the PR is green (`gh pr checks <n>` all pass; a docs-only PR that reports no checks is merged on the local gates), (b) the review tier passed (below), (c) the PR body carries the six defect-fix-contract items for fix slices and the slice's R-ids for every slice. Confirm `state=MERGED` before deleting the branch in a separate command. Never merge a PR with a failing check by any override. Production is never deployed by this run. Docs-only is decided by `gh pr view <n> --json files`: every changed path must match `docs/**` or `*.md`; a PR with any other path and no successful PR-gate run is never merged, and a `cancelled` or `skipped` check counts as not green.
6. **Review tiers (owner rule R9):** Tier A (fresh `opus` reviewer, adversarial, `Why Opus: Tier A — <reason>`, `Budget: 20 min wall-clock, 40 tool calls`) for any slice that writes or deletes rows, changes a migration, a hook, CI, the scheduler/cadence, budgets, the write path, or a repair tool; one round by default, a second round on the changed lines only when the first found CRITICAL or MAJOR; every MAJOR/CRITICAL fixed before merge. Tier B (`sonnet`, diff-only, `Budget: 10 min, 20 tool calls`) for ordinary code with green tests. Tier C (no review) for docs, ledger, config text. Unsure A/B → A. The reviewer's verdict must include "covers the class: yes/no" for fix slices. Every Tier A review MUST include a mutation check: the reviewer breaks each new guard or predicate in a scratch copy and shows the slice's test turning red; a guard whose mutation leaves the suite green is a CRITICAL finding. Every reviewer brief carries the build card, the slice's R-ids, the full diff, the red/green evidence, and the instruction that the PR body's claims are unverified assertions to be re-checked, not context. For Tier B slices the reviewer names ONE mutation of the changed behaviour that the new test must catch and confirms it does; a test that asserts nothing the diff changed is a MAJOR finding. A MAJOR finding at any tier blocks the merge until fixed and re-verified; a MINOR is fixed in the slice or filed as an issue with the PR number. For every Tier A item, the item close includes a rollback rehearsal on staging: the flag is turned off for one cycle (by the slot-default mechanism's env override, requested from the owner in the landing note) or, where no flag exists, the card's Rollback section is executed on staging and the cycle line shows the prior behaviour; the result is recorded beside the proof line. Until the owner confirms the rehearsal, the item is DONE-PENDING-ROLLBACK, listed in the report.

## Failure-recovery budget

- Per slice: 10 fix attempts on a red gate (5 inline → `/fix-loop` → `/systematic-debugging`), then the slice is DEFERRED with the exact failing line, the item is marked BLOCKED-TECHNICAL, an issue is filed, and the run moves to the next item; never halt the run for one slice.
- Worker over budget or silent > 20 min (owner rule R7 tick): stop it, re-brief once with half budget, then defer.
- CI red for a reason outside the slice (main red, runner outage): fix main first if the cause is in this repo; if it is GitHub, wait 30 min twice, then record BLOCKED-EXTERNAL and continue local work on the next slice without pushing.
- Tunnel down: restart per recipe §1 twice; then the slice's integration test is OWED, recorded, and re-run before the item closes.
- Hard halt only: a precondition (b)/(e) failing; a write to `ipodhan` or `ipodhan_staging` detected outside the repair-tool path; a contradiction between two owner decisions; the daily PR cap reached (halts PR opening only). Context-budget anxiety is not a halt: append a continuation note and keep going.
- At most three review rounds per slice; on a fourth the slice is DEFERRED, BLOCKED-REVIEW is recorded with the unresolved finding, and the run moves on.
