## §1 Speed levers (owner-approved)

1. **Fuller slices.** A slice plan targets **250–400 changed lines** per slice (the cap stays 400). A slice under ~150 lines is merged with its neighbour unless it is a fix slice, a migration-only slice, or the tier differs. Pre-made plans under `docs/contracts/plans/` are re-cut to this size by the lane at Stage 1a before use.
2. **Tiers applied as written, not upward.** Tier A only for a slice that writes or deletes rows, changes a migration, a hook, CI, the scheduler or cadence, budgets, the write path, or a repair tool. Everything else with green tests is Tier B (`sonnet`, diff-only, 10 minutes). "Unsure A/B → A" stands, but "unsure" means the reviewer cannot say which list the slice falls in, not caution by habit. The tier is stated in the slice plan and checked by the verifier against this list.
3. **Second and later review rounds read only the changed lines**, and every reviewer starts from the mutation list in the slice plan (the pre-made plans carry one per slice). Three rounds max stands.

## §2 Reviewer and builder brief rules (every brief, every lane)

4. **Reviewer, first line:** *Build the case that would falsify the claim, then run it.* Examples that earned this today: a check that said "ignored" was asked about an invented directory (it said "ignored" again); a rebase story was tested with `git merge-tree` (0 removals); a "non-existent path" rule was tested with a directory that exists (still wrong). A comment's stated REASON is a claim to test, not context; a worker's "exit 0", "killed", "clean tree" or "posted" is a claim until reproduced. A guard whose mutation leaves the suite green is CRITICAL; a test that could not have failed either way proves nothing and is said so.
5. **Builder brief:** verify any instruction that names a checker, a syntax or a gate against the checker itself, and follow the checker over the brief (a relayed instruction was wrong three times today). Assert against a path the test itself generated, never a literal (cross-OS). Temp files go to `$TEMP`, never the checkout. Any brief that lets a worker mutate shared state (a test database, a fixture, a baseline) ends with the worker re-asserting that state and pasting the proof.

## §3 Corrections to contract text

6. **Rebase.** Replace every "rebase before create and before merge" instruction with: rebase with the merge-base form (`base=$(git merge-base HEAD origin/main); git fetch origin && git -c core.autocrlf=false rebase --onto origin/main $base`) **once, as the last action before `gh pr merge`**, and before `gh pr create` only when main has gained a new CI gate or changed a file the slice touches. Never reflexively: each force-push cancels the in-flight check run and the cancelled run counts against the shared cap. The reasons are CI validity (a green on a stale base does not describe the current gate set) and semantic interaction, **not** deletion: git merges from the merge-base, so files main gained after the base survive; "deletions" in `git diff origin/main HEAD` are a comparison artifact.
7. **Decision 11 (flags).** Delete "add `DEPLOY_SLOT` to both required-key lists in `scripts/assert-env-keys.sh`" (that script checks static env files; the slot is injected at pm2 start; requiring it would refuse every deploy). The slot reaches the processes through the pm2 environment export in `scripts/deploy-linux.sh`; the proof is the staging cycle log printing the slot and each flag's state. **The slot-aware helper applies to NEW flags only**; every flag already on `origin/main` keeps its `=== 'true'` reading and is never converted; a slice that must change an existing flag's default is BLOCKED-OWNER with the flag name and the exact question.
8. **Line endings.** Keep the staging discipline for `docs/ops/prod-ops-recipes.md` (`git -c core.autocrlf=false add`, or rely on the `.gitattributes` rule now on main); the reason is churn (hundreds of changed lines around a few real ones, unreviewable across three lanes), **not** command splitting: EOL conversion never touches a literal backslash-r.
9. **Decision 8 (tzcase).** The `vitest.tzcase.config.ts` run exits 1 on unmodified main and is invoked nowhere (#478). Until lane A's #478 slice wires it behind `npm run test:tzcase` (or retires it), no brief cites that command; after, briefs cite the npm script.
10. **Notifier.** Every contract's §0.3 gains: from this laptop, `NOTIFIER_URL=https://firekaro.com/notifier-gw`, project `ipodhan`, header `X-Api-Key` from `NOTIFIER_KEY_IPODHAN` in `D:/Abhay/GLOBAL.env`, read in its own statement and unset after (an env-prefix on the same line as the request sends an empty header and gets a uniform 401); severities are exactly `P0|P1|P2|info`; never into a file or a log. **Stage 0 gains a channel assertion:** post one `info` no-op and record the HTTP status; anything but 202 is a failed precondition. A "Notifier line" that was never posted is a contract breach, not a skip.
11. **Counting.** Every count of CI runs uses `--limit 100` and an IST-midnight-as-UTC filter; every "known" failure names its issue; a check that is red on known residue gets the residue repaired or the rows registered by id in a shrink-only baseline that the check reads exact-match, never left red (#472 → #401 was closed while the signal stayed red; that close was wrong).
12. **Stray processes.** A sweep filters positively for what the run could have started (node, tsx, vitest, find, grep, rg, drizzle-kit, ssh with the repo path or the run's worktree in the command line) and prints the whole list, never a top-N. A `find /` is banned. Kill by PID, never `pkill -f`. **An `ssh.exe` that owns a LISTEN on local port 15432 or 5432 is the database tunnel and is never killed** (`Get-NetTCPConnection -State Listen -LocalPort 15432,5432`).
13. **Timestamps.** Every timestamp, board writes included, comes from `date` read in the same command; board documents carry `timestampSource`. A migration journal entry is checked for future-dating (5-minute tolerance) after every `db:generate`.
14. **Traceability.** Item 20's check runs in reporting mode until the release that carries item 6 (its card says so); the enforce flip is an item 6 slice with #469 resolved first and the unclaimed count re-measured at flip time. Test headers are one comma-separated line: `// implements: R-nnn, R-nnn`.
15. **Shared ownership decided today:** the config loader `scraper/src/config/validated-config-loader.ts` is lane C's (merged #473); lane B's item 22 imports it.
