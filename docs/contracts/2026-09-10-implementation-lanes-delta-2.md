## §1 Throughput (owner asked at 21:0x IST whether the speed is satisfactory; the answer was no)

1. **Batch Tier B slices.** Two or three Tier B slices of the same item that touch disjoint files ship as ONE PR (one PR-gate run, one diff-only Sonnet review; the 400-changed-line cap applies per PR, so batch small slices, not large ones). Tier A slices stay one per PR.
2. **Runs, not merges, are the budget.** The shared counter (`scripts/ops/pr-gate-count.mjs`: IST day, `--limit 100`, prints its own stop provenance) is the only count anyone quotes; `--created=<UTC date>` undercounts by the early-IST runs and is banned. The supervisor sets the nightly stop in the ledger each evening (`PR_GATE_STOP=NN`); the owner's cap is 60; runs above the stop are for a red **main** only, never for a lane's own red PR.
3. **No reflex rebases.** Rebase only when main touched a file the slice changes or gained a CI gate. When the file is a workflow, a clean textual merge is also checked for semantic position (a step must still sit inside the runtime window it needs, e.g. between the Node 22 setup and the Node 20 restore). **Before opening any PR:** `git merge-base origin/main <branch>` against `git rev-parse origin/main`; a merge-base that predates a squash merge of work already on main means the PR diff will re-apply that whole slice (lane B: 599 lines shown for a 131-line change); rebase `--onto origin/main` off the old tip. Size is the symptom; the merge-base is the cause.
3b. **The 400-line cap reads SOURCE lines** (non-test, non-fixture). Test lines are listed separately in the PR body and are not capped; a test file over ~300 lines carries one sentence saying why. A guard and the only test that can fail it are one PR, never split (lane A #518: 68 source lines, 511 test lines, 195 of them because mutation showed two guards had no failing test).
4. **Lane rebalance** (recommended to the owner; in force only once the owner types the split line in both lane windows): items 15 and 13 move from lane A to lane C after item 2.

## §2 Proof rules (every brief, every PR body, every ledger proof line)

5. **A check is proven to execute by a CI run URL whose step log names the test**, pasted in the PR body; reading the workflow YAML is not confirmation. Integration tests under `scraper/tests/integration/` run only if listed on `pr-gate.yml`'s explicit allow-list (until lane A's s11 flips it to a directory glob with a reasoned skip-list); a new integration test is added to that line in the same PR and the body says so (#507: 17 files, 6 listed, 11 never ran).
6. **A passing proof is evidence only if it could have failed for the thing being claimed.** A snapshot over matrix keys cannot see a name that stopped being a key (item 3); a parity test below a wrapper cannot see the wrapper's branch (12-B); a predicate test is not branch coverage (M2 on #512). The brief states what would have made the proof red.
6b. **A real fixture must also be one that can FAIL for the fields under test** (lane B, item 8): two genuinely captured documents proved nothing because neither issuer publishes the numbers being extracted (an asset reconstruction company has no inventory ratios and declined a peer table). A brief names, per fixture, the field values it contains and the page they sit on; a fixture with none of them is not a fixture for that item.
7. **Before/after comparisons enumerate a name list fixed BEFORE the change**, never the keys after it; both directions gave false answers on 2026-09-10.
8. **Probe under the same runner, working directory and entry as the invocation being defended.** `@ipodhan/shared` resolves through `scraper/tsconfig.json` under tsx from `scraper/`, and through `node_modules` under vitest and under tsx from the repo root (the root `tsconfig.json` has no `paths` block). A worktree's alias target is proven by a marker probe or by lane A's s14 preflight, never inferred from junction topology. **The marker goes in the file the test under defence actually imports**, never in `packages/shared/src/index.ts`: the scraper imports shared utilities by subpath (`@ipodhan/shared/utils/<name>`, mapped by `packages/shared/package.json` `exports` straight to the source file), so `index.ts` is never touched and a marker there reads as "alias resolves to main" when the tree is fine (lane C, 12-B). Recipe: insert the marker into the changed file itself; run one test that genuinely exercises that function under the runner, working directory and entry being defended; confirm the marker is SEEN (the probe goes red before its green is trusted); restore from `.bak`; confirm `git status --porcelain` is empty. **Until a tree is probed, its alias-importing local results are UNVERIFIED and CI is the gate.** Exposure exists only where the branch changes `packages/shared`. Worktrees are created with `wt-new.ps1` **and** `wt-link-modules.ps1`; hand-rolled junctions are banned (#514, per-tree).
9. **Audit a merged PR by its merge commit** (`git diff --name-only <sha>^ <sha>`), never branch tip against a moved `origin/main` (that comparison manufactured four phantom `packages/shared` files in an audit looking for exactly that).
10. **A zero from a `--since` or date-filtered query is reported only with a companion count known to be non-zero** (`git log --since=<date>` returned 0 on a day with merges).
11. **A claim about a file cites the file's own header or first statements, read to the end of the passage**; three times on 2026-09-10 the disproof sat inside the cited artifact, the third being a header whose next line answered the contradiction being reported.
12. **A test database is not a mirror of main.** A slice that touches schema asserts the test DB's state against the migrations journal before trusting green (`ipodhan_test` carried a stray `heading_hash` column from earlier testing).
12b. **Three string-function traps, each caught by running, never by reading** (lane C, 12-B): a `$`-anchored strip placed before whitespace collapse never fires while the code reads correct, so order of operations is pinned by a test input with trailing whitespace; a single backslash inside a SQL template literal (three times on 2026-09-10) is caught only by the TypeScript-vs-SQL agreement test, which is why it is committed red first; when a behaviour change shortens a literal in an existing test, update only the literal and keep the property assertion, because updating a test to match new behaviour is how a regression gets buried. A key rule measured clean on today's data is narrowed to the shape it needs (trailing country token only, not after "of"/"for"), because measured-today is not safe-forever.
12c. **Mutate one guard at a time.** A combined mutation of several guards yields a failure count, not the identity of which guard fired; lane A named the wrong guard as covered from a three-at-once run and found it only by re-running them singly.
12d. **An owner-set limit is changed only by owner-typed text in the lane's own window.** The supervisor announcing "cap lifted" on the owner's word to the supervisor is a relay, not approval; the lane that refused it (lane A, 2026-09-10 22:2x) was right. The supervisor's job is to hand the owner the exact line to paste.
13. **A new table needs both the journal count and the expected table set** in the stage-0 replay test; a migration idx is PROVISIONAL until re-read from `origin/main` at merge.

## §3 Hygiene

14. **A held slice is pushed to origin the moment its build is proven**; three lane C slices sat local-only in worktrees for hours, where a sweep would have destroyed them.
15. **The board is written in the same command as the ledger line** (lane A s15 couples them in tooling); a board more than 60 minutes behind its ledger is a defect. The supervisor's staleness reading uses `date`, not an estimate; the supervisor got this wrong once on 2026-09-10 and reported 95 minutes for 33.
16. **`wt-rm` refusing a branch with zero commits of its own means local main is stale**: fast-forward and re-run, never `-Discard`.
17. **Every timestamp comes from `date` in the same command**, supervisor included.
17b. **Long jobs report as they go**, one unit per process, appending each result immediately; a job that prints only on success is indistinguishable from a hung one and, when killed for memory, unrecoverable (lane B lost an 11-minute four-RHP probe this way). A port probe that TIMES OUT is not "port down"; it may be in use by another lane's tunnel.
