## Pre-made design decisions (owner, 2026-09-09 interview; the run must NOT pause on these)

Add each to §0.0.1 as **OD-27 … OD-51**, quoted as below, dated 2026-09-09, each pointing at the section that implements it, each with a D10 signature. Where a new decision replaces an earlier one, mark the earlier row `SUPERSEDED by OD-nn` (never delete it).

1. **OD-27 locks.** The live-figures job has its own lock. The data job and the 22:00 closed-IPO job share the heavy lock. The data job never blocks the live-figures job. (§2.1)
2. **OD-28 = O-13 decided.** Grey-market premium runs every 30 minutes whenever any IPO is UPCOMING or OPEN; subscription and the demand graph only during bidding hours (10:00–18:30 IST) on days an IPO is OPEN. Move O-13 from §0.0.2 to §0.0.1; F-76 leaves TRIGGERED.
3. **OD-29 post-listing prices.** From the free NSE and BSE public quote endpoints the scrapers already use: every 15 minutes during market hours for 90 days after listing, then stop; the page shows the last price with its date, labelled "delayed". No broker feed (Kite, Angel One SmartAPI, Upstox) reaches the public site: redistribution needs an NSE Data and Analytics licence. Owner's words: *"yes I accept 15-minute delayed prices from the exchanges' public endpoints, with the 90-day windows."* (new §2.1 row + §1.9)
4. **OD-30 same-type and corrigendum rules.** Within one document type the later filing date wins and a re-extraction of an older filing never overwrites a value from a later one. A corrigendum overrides only the fields it names and freezes them against every earlier document of any type until a newer corrigendum or the final prospectus. The final prospectus is terminal; after it only a corrigendum to the prospectus changes a document-owned field. Each rule has a named test. (§2.5 / §3)
5. **OD-31 opening-day check.** A discovery-only check at about 09:45 IST on days an IPO is due to open: fetch the two exchange lists, register any new or changed IPO so the live-figures job sees it; no documents, no verification. The exact time is set by probe `probes/exchange-list-change-time.mjs`, which records when each exchange's list changes on the next three opening days (or, if none falls inside the run, on the most recent three from saved fixtures with the method stated), and is placed 15 minutes after the later of the two. (§2.1)
6. **OD-32 document lifecycle, REPLACES OD-23.** Owner: *"we read the document, retain it for a week so that we re-read it if previous reads were not successful and then delete it."* Download once, extract once, store the extracted plain text with page numbers for the life of the IPO row; keep the PDF seven days after its **last successful extraction**, then delete; every later re-read (website disagreement, extractor fix) works from stored text and never re-downloads; the 5 GB ceiling stays. Mark OD-23 `SUPERSEDED by OD-32`; rewrite §0.5.1 and §6's retention text; D-check signature updated; check **D17**: no section keeps a PDF beyond seven days after extraction and no section schedules a re-download of an already-extracted document.
7. **OD-33 one download, one read.** Owner: *"once a scraper scrapes an IPO data, scraper should not rescrape the same document for same IPO again. if any new IPO document comes only then the scraper should scrape the new document for an existing IPO."* Stated as a rule with a named test: sha256 identity means no re-download and no re-extract (already `document-state-machine.ts` ~670); a COMPLETED document is never re-extracted except on extractor version change for a failed field or a §3 re-read from stored text; the per-slot discovery page fetch is allowed and stated; the timed backoff retry (15 min doubling to 6 h, 10 attempts) is removed (OD-21). (§2.1, §2.5)
8. **OD-34 identity binding order.** CIN, then the SEBI draft filing number, then the exchange symbol, then the normalised name; a name-only row is flagged `name-bound` until an identifier arrives; a test uses a real rename pair found by probe. (§2.3)
9. **OD-35 one row is one offering.** Same identifier and open dates within 180 days (or one not yet open) = same offering; an offering-type change (IPO → FPO) = new row; a `company_id` links rows of one company. **Lapsed-draft rule** (owner's scenario): a new draft for a company whose existing row has no open date → if that row is WITHDRAWN, or its draft is older than twelve months with no RHP, the old offering lapsed: freeze it with a forward-linking notice (OD-8 mechanism) and create a new row; otherwise it is a re-filing of the same offering (S-05). (§2.3)
10. **OD-36 document handling.** Multi-part filings extracted per part with the part number in provenance; image-only pages detected by text density and routed to OCR, marked OCR with lower confidence; a blank password tried once, then unreadable with cause, no retry; content sniffed before store (a non-PDF is not stored, cause recorded); the exchange's stable document identifier stored beside the URL. One real fixture per rule, from the live source. (§2.2 or a new §2.2.1)
