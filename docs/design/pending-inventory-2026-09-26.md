## How this was made, and how far to trust it

- Owner scope (2026-09-25): every open GitHub issue plus every non-final board status plus the three PARTIAL items; skip anything on hold (label `parked`, or parked by its own comment). Production is out of scope (`staging-is-the-release-gate.md` R1) and gets one noted section.
- Owner direction: an issue is not a requirement. Each was checked against the spec (`data-sourcing-pull-model.md`, OD rows, `findings.json`) and the code: conforms and not built = BUILD; contradicts the spec = REJECT; new behaviour the spec does not cover = OWNER CALL.
- 169 open issues. Pass 1: six readers, one per ~28 issues. Pass 2: five independent verifiers re-checked every FIXED and BUILD verdict against `origin/main` and ran data reads on staging. The supervisor then re-checked the contested ones (prod tag, CI config, plan-row ages).
- **Limits, stated plainly.** Pass 2 overturned 5 of 53 "fixed" verdicts (#98, #453, #695, #771, #890), so pass-1 verdicts alone are not trustworthy. About 40 BUILD verdicts were re-checked by pass 2; the rest rest on one reader's cited file:line evidence. The goal's first step on each BUILD item is therefore to re-read it on `origin/main` before building (a cheap check, not a re-triage).
- Closing rule (signal-ownership R5): an issue is closed only when every fix commit is on the prod tag, or the defect never reaches production (tests, CI, dev tooling, a record). A real fix that is only on main is **FIXED ON MAIN** and stays open until the release.
